## Base URL

```text
https://api.narriflow.example/api/v1
```

All requests use HTTPS and JSON. The [OpenAPI 3.1 document](https://api.narriflow.example/api/v1/openapi.json) describes every endpoint, so you can import it into an HTTP client or generate a typed client from it.

Changes within v1 only add endpoints and optional fields. Breaking changes ship under a new version path.

## Authentication

Send a Workspace API key as a Bearer token.

```text
Authorization: Bearer nf_…
```

<Steps>
  <Step title="Open Developer access">
    In the app, go to **Settings → Developer access**. You need the Owner, Admin or Editor role, and the Workspace must be active and on the Pro or Business plan.
  </Step>
  <Step title="Create a key">
    Name the key and choose its permissions. A new key can read projects, exports, usage, Autopilot and publishing. Each write permission is opt-in.
  </Step>
  <Step title="Copy the key">
    Narriflow shows the key once. Store it in a secret manager and never put it in code or client-side apps.
  </Step>
</Steps>

A key acts only in its own Workspace, with its scopes and with its creator's current role. If the creator leaves the Workspace, the key stops working. OAuth tokens do not work with this API.

## Scopes

| Scope | Endpoints |
| --- | --- |
| `usage:read` | `GET /workspace` |
| `projects:read` | `GET /brand-profiles`, `GET /recipes`, `GET /recipes/{id}`, `GET /library/search`, `GET /projects`, `GET /projects/{id}`, `GET /projects/{id}/clips`, `GET /clips/{id}`, `GET /events` |
| `processing:write` | `POST /uploads`, `GET /uploads/{id}`, `POST /uploads/{id}/grants`, `POST /uploads/{id}/finalize`, `DELETE /uploads/{id}`, `POST /projects`, `POST /projects/{id}/generations` |
| `exports:write` | `POST /clips/{id}/exports` |
| `exports:read` | `GET /exports/{id}`, `GET /exports/{id}/download`, `GET /clips/{id}/timeline` |
| `publishing:read` | `GET /social-accounts` |
| `publishing:write` | `POST /social-posts/proposals` |

`GET /operations/{id}` needs `projects:read` for imports and generations, and `exports:read` for exports. `POST /operations/{id}/callback/redeliver` needs `processing:write` or `exports:write` the same way. `GET /events` also needs `publishing:read` to include `social_post.proposed` and `social_post.finished` events; without it they are left out. A missing scope returns `403 scope_required` and names the scope.

## Plan and credits

The API needs an active Workspace on the Pro or Business plan. Other plans get `402 plan_feature_required`, with `details` naming the feature, the current tier and the required tier. An inactive Workspace gets `402 integration_access_unavailable`. A command whose own feature the plan lacks, such as review rooms on Pro, or that goes past a plan limit, returns `402 plan_feature_required` or `402 plan_limit_reached` the same way.

Importing and uploading use the Workspace's credits, exactly as in the app. `GET /workspace` returns `usedCredits`, `reservedCredits`, `remainingCredits` and `limitCredits` for this UTC month, `periodStart` and `renewsAt`, the videos in flight, and the per-video length limit. New imports are refused with `429 workspace_processing_capacity_reached` while the plan's number of videos is already importing or processing; retry after the `Retry-After` delay.

- One credit is one started minute of source video, counted per video from its measured length: 1 second uses 1 credit, 60 seconds uses 1, and 60.01 seconds uses 2. The whole video counts, even when you process only part of it. The per-video length limit also uses the measured length, so a video even a fraction of a second over the limit is refused.
- Credits are reserved when Narriflow accepts the video and settled from its real length before transcription. A video that never starts processing gives its credits back.
- Credits renew at 00:00 UTC on the first of each month (`renewsAt`). Unused credits don't roll over.
- Retrying or regenerating the same Project is free. Importing the same video again as a new Project uses credits again.
- A video that needs more credits than are left is refused with `402 credits_exhausted`.

## Idempotency

Requests that start work need an `Idempotency-Key` header of 1 to 200 characters from `A-Z a-z 0-9 . _ ~ : -`. This covers opening an upload, submitting a link, generating clips, exporting, and redelivering callbacks.

- Retry a lost request with the same key and body to get the original result. The response carries `Idempotent-Replayed: true`.
- The same key with a different body returns `409 operation_idempotency_conflict`.
- Keys belong to the person who created the API key. A retry after you rotate the key still returns the original result.

In loops, build keys from the run, the item and the action, for example `run-81:item-3:export`. Upload grants, finalize and discard are addressed by Upload Session ID and are safe to repeat without a key.

## Operations

A request that starts work returns `202` with an `operation` holding an opaque `operationId` and a `statusUrl`. Read it with `GET /operations/{id}` or have Narriflow call you back. The state is `working`, `completed`, `partial`, `failed` or `cancelled`, with progress, each clip's or format's outcome, and the IDs produced. An intake follows its upload or import into the clip generation it starts. See [Completion callbacks](/docs/api/callbacks), and [Events](/docs/api/events) or [Webhooks](/docs/api/webhooks) for work that no request of yours started.

## Errors

Errors share one shape.

```json
{
  "error": "scope_required",
  "message": "This credential requires the projects:read scope",
  "requestId": "req_0b6f…",
  "details": { "scope": "projects:read" }
}
```

`requestId` also arrives in the `X-Request-Id` header. Include it when you contact support. Some errors add `retryAfterSeconds`.

| Status | Meaning |
| --- | --- |
| 400 | The request is invalid, or `Idempotency-Key` is missing or malformed. |
| 401 | The key is missing, invalid or revoked. |
| 402 | The plan doesn't include the feature or limit (`plan_feature_required`, `plan_limit_reached`), the Workspace isn't active, or its credits are used up. |
| 403 | The key lacks a scope, or your role or Workspace does not allow the action. |
| 404 | The resource does not exist in the key's Workspace. |
| 409 | A conflict, including an idempotency key reused with different input. |
| 422 | Narriflow cannot process the request, for example a video that is too long. |
| 429 | Rate limited, or the Workspace has too many videos processing. Honor `Retry-After`. |
| 503 | Temporarily unavailable. Honor `Retry-After`. |

## Rate limits

Each key can send 300 requests a minute. Responses carry `RateLimit-Limit` and `RateLimit-Remaining`. Requests with a missing, invalid or revoked key count separately, by client address: after 600 failures in a minute, that address gets `429 rate_limited` until the minute ends, even with a valid key. If the limiter is briefly unavailable, reads and retries of accepted requests still succeed, and new work returns `503 mutations_unavailable`.
