---
title: Completion callbacks
description: Have Narriflow call your server when an upload, import, generation or export finishes, signed with the Standard Webhooks format.
---

A callback is one signed `POST` to a URL you choose. It carries IDs only. After you receive it, call the API for the project, clips or files.

<Steps>
  <Step title="Create the signing secret">
    In **Settings → Developer access**, find **Completion callback signing secret** and select **Create secret**. Copy the `whsec_…` value. Narriflow shows it once.

    Without a secret, a request that includes a callback returns `409 callback_secret_required` and no work starts.
  </Step>
  <Step title="Add a callback to a request">
    Add `"callback": { "url": "https://…" }` to the body of `POST /uploads/{id}/finalize`, `POST /projects`, `POST /projects/{id}/generations` or `POST /clips/{id}/exports`.

    The URL must be public HTTPS on port 443 and at most 2,048 characters. A request registers at most one callback. The URL is part of the request, so retrying with a different URL is a conflict.
  </Step>
  <Step title="Verify and handle the event">
    Check the signature on every delivery before you trust the body. See [Verify a callback](#verify-a-callback).
  </Step>
</Steps>

## The event

```json
{
  "id": "5b1c3a52-9f0e-5d6a-8c1b-2e7d4f9a0b13",
  "type": "operation.completed",
  "version": 1,
  "createdAt": "2026-10-08T12:00:00.000Z",
  "workspaceId": "00000000-0000-4000-8000-000000000002",
  "data": {
    "operationId": "op_…",
    "kind": "intake",
    "state": "completed",
    "projectId": "00000000-0000-4000-8000-000000000004",
    "clipIds": ["00000000-0000-4000-8000-000000000009"]
  }
}
```

| Field | Meaning |
| --- | --- |
| `id` | The event ID. It also arrives as the `webhook-id` header and stays the same across retries. |
| `data.operationId` | The operation that finished. Read it with `GET /operations/{id}`. |
| `data.kind` | `intake`, `generation` or `export`. |
| `data.state` | `completed`, `partial`, `failed`, `cancelled` or `unavailable`. |
| `data.projectId` | The project the work belongs to. |
| `data.clipIds` | Present when clips were produced. |
| `data.exportId` | Present for exports. |
| `data.failureCode` | Present when the state is not `completed`. |

The response that accepts a request with a callback returns `callback.eventId`, so you know the event ID before it arrives. An event can arrive a few minutes after the work finishes.

## Verify a callback

Each delivery carries three headers.

| Header | Value |
| --- | --- |
| `webhook-id` | The event ID. |
| `webhook-timestamp` | Unix time in seconds when this attempt was signed. |
| `webhook-signature` | One or more `v1,<base64>` signatures separated by spaces. |

The signature is an HMAC-SHA256 of `id.timestamp.body`, keyed with the base64-decoded secret without its `whsec_` prefix. Use the raw request body, not re-serialized JSON.

<CodeGroup>

```typescript TypeScript
import { Webhook } from "standardwebhooks"; // npm install standardwebhooks

interface CompletionEvent {
  type: string;
  data: { operationId: string };
}

const webhook = new Webhook(process.env.NARRIFLOW_CALLBACK_SECRET!); // whsec_…

export async function POST(request: Request): Promise<Response> {
  const body = await request.text();
  let event: CompletionEvent;
  try {
    event = webhook.verify(body, {
      "webhook-id": request.headers.get("webhook-id") ?? "",
      "webhook-timestamp": request.headers.get("webhook-timestamp") ?? "",
      "webhook-signature": request.headers.get("webhook-signature") ?? "",
    }) as CompletionEvent;
  } catch {
    return new Response("Invalid signature", { status: 400 });
  }
  // Delivery is at least once. Skip an event ID you have already handled.
  // Then call GET /operations/{event.data.operationId} for the current state.
  return new Response(null, { status: 204 });
}
```

```typescript Node.js (TypeScript), no library
import { createHmac, timingSafeEqual } from "node:crypto";

export function verifyCallback(secret: string, headers: Record<string, string | undefined>, body: string): unknown {
  const id = headers["webhook-id"];
  const timestamp = headers["webhook-timestamp"];
  const signatures = headers["webhook-signature"];
  if (!id || !timestamp || !signatures) throw new Error("Missing webhook headers");
  if (Math.abs(Date.now() / 1000 - Number(timestamp)) > 300) throw new Error("Stale timestamp");

  const key = Buffer.from(secret.replace(/^whsec_/, ""), "base64");
  const expected = createHmac("sha256", key).update(`${id}.${timestamp}.${body}`).digest();
  const valid = signatures.split(" ").some((entry) => {
    const [version, signature] = entry.split(",");
    if (version !== "v1" || !signature) return false;
    const actual = Buffer.from(signature, "base64");
    return actual.length === expected.length && timingSafeEqual(actual, expected);
  });
  if (!valid) throw new Error("Invalid signature");
  return JSON.parse(body);
}
```

```python Python
import os

from flask import Flask, request
from standardwebhooks import Webhook, WebhookVerificationError  # pip install standardwebhooks

webhook = Webhook(os.environ["NARRIFLOW_CALLBACK_SECRET"])  # whsec_…
app = Flask(__name__)


@app.post("/narriflow")
def narriflow():
    try:
        event = webhook.verify(request.get_data(), dict(request.headers))
    except WebhookVerificationError:
        return "Invalid signature", 400
    # Delivery is at least once. Skip an event ID you have already handled.
    # Then call GET /operations/{event["data"]["operationId"]} for the current state.
    return "", 204
```

</CodeGroup>

Reject events whose timestamp is more than five minutes old, and keep the event IDs you have handled so a repeat delivery does nothing.

<Warning>
  Anyone who holds the signing secret can verify, and forge, events for the whole Workspace. Give it only to receivers you trust.
</Warning>

## Delivery

- **At least once.** Any `2xx` response marks the event delivered. A `410` response stops delivery.
- **Retries.** Anything else, including a timeout after 10 seconds, retries after about 30 seconds, 2 minutes, 10 minutes, 30 minutes, 1 hour, 3 hours, 6 hours, 12 hours and 24 hours, each varied by up to 20 percent. Then Narriflow stops. Narriflow signs every attempt with a fresh timestamp.
- **No redirects.** Narriflow does not follow them.
- **Redelivery.** `POST /operations/{id}/callback/redeliver` resets the operation's delivered or failed callbacks and sends them again with the same event IDs. It needs an `Idempotency-Key` header and returns `404 callback_not_found` if the operation has no callback.

## Rotate the secret

Select **Rotate secret** in **Settings → Developer access**. For 24 hours, each event carries signatures from both the new and the previous secret, so receivers using either one keep working. Update your receiver to the new secret within that window.
