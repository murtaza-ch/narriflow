## Base URL

```text
https://app.narriflow.com/api/v1
```

All requests use HTTPS and JSON. The [OpenAPI 3.1 document](https://app.narriflow.com/api/v1/openapi.json) describes every endpoint, so you can import it into an HTTP client or generate a typed client from it.

Changes within v1 only add endpoints and optional fields. Breaking changes ship under a new version path.

## Authentication

Send a Workspace API key as a Bearer token.

```text
Authorization: Bearer nf_…
```

<Steps>
  <Step title="Open Developer access">
    In the app, go to **Settings → Developer access**. You need the Owner, Admin or Editor role, and the Workspace must be on an active Business plan.
  </Step>
  <Step title="Create a key">
    Name the key and choose its permissions. A new key can read projects, exports, usage, Autopilot and publishing. Each write permission is opt-in.
  </Step>
  <Step title="Copy the key">
    Narriflow shows the key once. Store it in a secret manager and never put it in code or client-side apps.
  </Step>
</Steps>

A key acts only in its own Workspace, with its scopes and with its creator's current role. If the creator leaves the Workspace, the key stops working. OAuth tokens do not work with this API.

## Scopes

| Scope | Endpoints |
| --- | --- |
| `usage:read` | `GET /workspace` |
| `projects:read` | `GET /brand-profiles`, `GET /projects`, `GET /projects/{id}`, `GET /projects/{id}/clips`, `GET /clips/{id}` |
| `processing:write` | `POST /uploads`, `GET /uploads/{id}`, `POST /uploads/{id}/grants`, `POST /uploads/{id}/finalize`, `DELETE /uploads/{id}`, `POST /projects`, `POST /projects/{id}/generations` |
| `exports:write` | `POST /clips/{id}/exports` |
| `exports:read` | `GET /exports/{id}`, `GET /exports/{id}/download` |

`GET /operations/{id}` needs `projects:read` for imports and generations, and `exports:read` for exports. `POST /operations/{id}/callback/redeliver` needs `processing:write` or `exports:write` the same way. A missing scope returns `403 scope_required` and names the scope.

## Plan and processing minutes

The API needs an active Business plan. Other plans get `402 integration_access_unavailable`.

Importing, uploading and generating use the Workspace's processing minutes, exactly as in the app. `GET /workspace` returns the minutes used, reserved and remaining this UTC month, the videos in flight, and the per-video length limit.

## Idempotency

Requests that start work need an `Idempotency-Key` header of 1 to 200 characters from `A-Z a-z 0-9 . _ ~ : -`. This covers opening an upload, submitting a link, generating clips, exporting, and redelivering callbacks.

- Retry a lost request with the same key and body to get the original result. The response carries `Idempotent-Replayed: true`.
- The same key with a different body returns `409 operation_idempotency_conflict`.
- Keys belong to the person who created the API key. A retry after you rotate the key still returns the original result.

In loops, build keys from the run, the item and the action, for example `run-81:item-3:export`. Upload grants, finalize and discard are addressed by Upload Session ID and are safe to repeat without a key.

## Operations

A request that starts work returns `202` with an `operation` holding an opaque `operationId` and a `statusUrl`. Read it with `GET /operations/{id}` or have Narriflow call you back. The state is `working`, `completed`, `partial`, `failed` or `cancelled`, with progress, each clip's or format's outcome, and the IDs produced. An intake follows its upload or import into the clip generation it starts. See [Completion callbacks](/api/callbacks).

## Errors

Errors share one shape.

```json
{
  "error": "scope_required",
  "message": "This credential requires the projects:read scope",
  "requestId": "req_0b6f…",
  "details": { "scope": "projects:read" }
}
```

`requestId` also arrives in the `X-Request-Id` header. Include it when you contact support. Some errors add `retryAfterSeconds`.

| Status | Meaning |
| --- | --- |
| 400 | The request is invalid, or `Idempotency-Key` is missing or malformed. |
| 401 | The key is missing, invalid or revoked. |
| 402 | The Workspace needs Business, or its processing minutes are used up. |
| 403 | The key lacks a scope, or your role or Workspace does not allow the action. |
| 404 | The resource does not exist in the key's Workspace. |
| 409 | A conflict, including an idempotency key reused with different input. |
| 422 | Narriflow cannot process the request, for example a video that is too long. |
| 429 | Rate limited, or the Workspace has too many videos processing. Honor `Retry-After`. |
| 503 | Temporarily unavailable. Honor `Retry-After`. |

## Rate limits

Each key can send 300 requests a minute. Responses carry `RateLimit-Limit` and `RateLimit-Remaining`. If the limiter is briefly unavailable, reads and retries of accepted requests still succeed, and new work returns `503 mutations_unavailable`.
