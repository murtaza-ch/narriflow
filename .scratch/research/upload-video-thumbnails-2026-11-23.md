# Thumbnails for selected and uploaded videos

Researched 2026-11-23. Read local `AGENTS.md` and the unslop skill. No app code changed. Findings below distinguish specified browser behavior, provider documentation, and proposed Narriflow policy. No browser or device benchmarks were run.

The WHATWG HTML specification defines normative canvas algorithms. The File API Editor's Draft defines blob-URL algorithms but is not a final W3C Recommendation. MDN explains APIs; web.dev and WAI tutorials give implementation guidance. Provider defaults apply to their services. None prescribes Narriflow's byte, dimension, quality, or timeout budgets. [HTML](https://html.spec.whatwg.org/multipage/canvas.html), [File API status](https://w3c.github.io/FileAPI/)

## Recommended behavior

Generate one small, temporary preview from the selected `File` in the browser. Start upload independently. After verified ingest, have the existing media executor generate and store the persistent poster. Return its authorized URL through the API and replace the temporary image after the persistent image loads. On refresh or another device, use the stored poster or a stable placeholder.

This is an engineering recommendation, inferred from browser URL lifetimes and provider poster APIs. The sources do not establish that Vimeo or YouTube use client-side extraction during upload. A blob URL references browser-managed data and is unsuitable as a persisted asset URL. [File API](https://w3c.github.io/FileAPI/#url), [MDN blob URLs](https://developer.mozilla.org/en-US/docs/Web/URI/Reference/Schemes/blob)

For Narriflow, keep temporary extraction in `apps/web`, permanent FFmpeg work in `apps/media`, and authorization/state in API/services, following local `AGENTS.md`. Do not make a successful browser preview an upload admission requirement or introduce a second media pipeline for it.

## What first-party products document

- Mux provides JPG, PNG, and WebP thumbnail endpoints with time, dimensions, and fit options. Its guide says frame selection defaults to `thumbnail_time` when set, otherwise the video's midpoint. Preserving aspect ratio is the default fit; crop, smart crop, stretch, and padding are explicit options. This documents configurable frame extraction, not a universally representative frame. [Image guide](https://www.mux.com/docs/guides/get-images-from-a-video), [API reference](https://www.mux.com/docs/api-reference/image/thumbnails/get-thumbnail)
- Cloudflare Stream defaults its player poster to the first frame. Its thumbnail endpoint defaults to time `0s`, width/height `640`, and crop. It supports explicit time, fit modes, and a per-video fractional `thumbnailTimestampPct`. Non-square-pixel videos are a documented limitation. [Stream thumbnails](https://developers.cloudflare.com/stream/viewing-videos/displaying-thumbnails/)
- Vimeo automatically selects a video frame after creation/upload and permits suggested images, uploaded images, and selecting a frame after optimization. Its newer product updates describe a slider for frame selection; the Help Center still describes playing and selecting a frame. Treat those controls as documented UX variants. [Help Center](https://help.vimeo.com/hc/en-us/articles/12426471350289-How-to-change-the-thumbnail-image-for-my-video), [Product updates](https://vimeo.com/product-updates)
- YouTube documents generated suggestions and custom thumbnail uploads. Its current page recommends `3840×2160` for videos and `2160×3840` for Shorts, with device-dependent upload limits. Those are publishing recommendations, not web standards or dashboard download targets. Changes may take time to appear. Avoid repeating older `1280×720` guidance as its current rule. [YouTube Help](https://support.google.com/youtube/answer/72431?hl=en)

Inference: automatic defaults plus optional editing are common. These sources provide no consensus for the first frame, midpoint, or a fixed percentage. A thumbnail editor is unnecessary for basic dashboard recognition.

## Browser extraction and failure handling

1. Create a source object URL from the selected `File`. Use a muted, inline, non-autoplay video element. Register handlers before assigning `src`. `preload="metadata"` is a hint, not a strict loading or memory budget; seeking still requires decoding media data. [MDN video element](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/video)
2. Wait for metadata to obtain duration and intrinsic `videoWidth`/`videoHeight`. Metadata alone does not mean frame pixels are available. Wait for a decoded first frame, or set `currentTime` and wait for `seeked` before drawing; check nonzero dimensions and `readyState >= HAVE_CURRENT_DATA`. Do not rely on a fixed sleep. Handle the zero-time path without assuming a no-op seek emits an event. [Metadata event](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/loadedmetadata_event), [seeked event](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/seeked_event), [drawImage](https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/drawImage), [videoWidth](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/videoWidth)
3. Scale directly into a bounded canvas, preserving aspect ratio. Export with `toBlob`, then create a separate image object URL. Handle missing canvas context, thrown errors, and a null blob. `toDataURL` encodes the whole image as an in-memory string; MDN recommends `toBlob` with object URLs for larger images. [toBlob](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/toBlob), [toDataURL](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/toDataURL)
4. Bound the whole operation, including metadata load, seeking, frame callbacks, and encoding. Cancel on replacement/removal/unmount and ignore stale completions. If extraction fails, retain the filename, file icon, and upload progress. A browser codec failure does not establish that the server cannot process the file. `canPlayType` returns likelihood, not a decode guarantee; media errors include decode and unsupported-source failures. [canPlayType](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/canPlayType), [MediaError](https://developer.mozilla.org/en-US/docs/Web/API/MediaError/code)

`requestVideoFrameCallback` can coordinate work with presented frames, but do not make it an unbounded dependency for a paused hidden extractor. It does not guarantee exact synchronization. [MDN frame callback](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestVideoFrameCallback)

Remote video extraction has another failure mode: canvas export throws `SecurityError` when the canvas is not origin-clean. Cross-origin media needs suitable CORS configuration. A locally selected file object URL avoids fetching the source from an external provider. [Canvas specification](https://html.spec.whatwg.org/multipage/canvas.html#dom-canvas-toblob-dev)

## Suggested budgets, not standards

- Start with one frame at `min(1 second, duration / 2)` for finite positive durations. This avoids the exact opening frame and stays within short clips. It can still select black frames, intros, or motion blur. Use the same timestamp policy server-side; add representative-frame analysis only if observed failures justify it.
- Size against the actual component. A 320 CSS-pixel-wide card needs roughly 640 image pixels for 2× density. Start with a 640-pixel maximum long edge for local previews, without upscaling. Portrait videos need height considered too; width alone is not a sufficient cap.
- Start JPEG at quality `0.8`, targeting roughly 30–100 KB for that local image. Measure real footage. This is a tuning target, not a guaranteed output size or upload rejection threshold. Dimensions often matter more than small quality adjustments. Add WebP only when its measured benefit justifies another format.
- Start with one extraction at a time and an overall 8-second deadline. Upload must continue if preview generation misses the deadline. These values need device measurements; no cited standard prescribes them.

The HTML standard specifies PNG fallback for unsupported canvas output types, a lossy quality range of `0` to `1`, and implementation-dependent quality interpretation. Check the returned blob's type and size. JPEG `0.8` is not an interchangeable quality setting across browser and FFmpeg encoders. [Canvas serialization](https://html.spec.whatwg.org/multipage/canvas.html#a-serialization-of-the-bitmap-as-a-file)

For persistent variants, derive sizes from measured CSS slots. Supply `srcset`/`sizes` for varying layouts or `1x`/`2x` for fixed slots. Pixel dimensions determine sharpness; a file's DPI metadata does not solve DPR. Reserve width/height or an aspect-ratio box to prevent movement. Load visible cards normally, lazy-load offscreen cards, and avoid marking every card high priority. [web.dev responsive images](https://web.dev/learn/design/responsive-images), [MDN sizes and DPR](https://developer.mozilla.org/en-US/docs/Web/API/HTMLImageElement/sizes), [web.dev lazy loading](https://web.dev/articles/browser-level-image-lazy-loading)

Use a consistent card box. Prefer containment when users need to recognize the full source frame, especially portrait footage; use cover only with an intentional crop. This is a UI choice, not a browser requirement.

## Lifetime, private media, and accessibility

Revoke the source URL after extraction stops and the video no longer needs it. Clear listeners/timers, pause the element, remove `src`, call `load`, and release references. Keep the thumbnail URL alive while its image remains usable; revoke on replacement/removal/unmount, not immediately after image load. File API URL mappings retain the blob until revoked or their environment goes away. [File API](https://w3c.github.io/FileAPI/#url), [MDN cleanup guidance](https://developer.mozilla.org/en-US/docs/Web/URI/Reference/Schemes/blob)

Treat persistent posters as private media. Mux requires signed image requests for signed playback IDs, with transformations included in token claims. Stream also requires a signed URL in place of the video ID when protection is enabled. Inference for Narriflow: authorize poster access with workspace access, avoid permanent public poster URLs for private videos, refresh expiring URLs through the API, and keep signing credentials out of web. [Mux signed playback](https://www.mux.com/docs/guides/secure-video-playback), [Stream thumbnails](https://developers.cloudflare.com/stream/viewing-videos/displaying-thumbnails/)

Use a new object key/version when replacing a poster. Mux explicitly warns that purging its CDN cannot purge a browser's existing cached image. For protected application responses, select caching deliberately: `private` permits browser caching, while `no-store` prohibits storage. Signed-URL expiry alone does not erase already cached pixels; align any permitted browser cache lifetime with the access policy. [Mux cache behavior](https://www.mux.com/docs/guides/set-a-default-thumbnail), [MDN Cache-Control](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Cache-Control)

If the thumbnail duplicates the adjacent filename/title in the same link, use `alt=""`. If it alone identifies the action, provide an accessible name such as "Open interview.mp4". Keep upload/error state in text, maintain keyboard access, and avoid autoplay previews for this task. WAI's image tutorials are implementation guidance, not themselves normative WCAG text. [Decorative images](https://www.w3.org/WAI/tutorials/images/decorative/), [Functional images](https://www.w3.org/WAI/tutorials/images/functional/)

## Open-source comparisons

Inspected source, not just package descriptions. Neither implementation was executed or audited as a dependency.

- [`pseudosavant/video-thumbnail.js`, commit fe23450](https://github.com/pseudosavant/video-thumbnail.js/blob/fe2345005eff11b518efa9392f994722bd2371b0/src/video-thumbnail.js) loads a video, seeks, scales to canvas, supports Blob/object-URL outputs, and clears the video source in `finally`. It provides load/seek deadlines and URL cleanup helpers. Its data-URI default, optional localStorage cache, pooling, retries, and timestamp convention add more machinery than Narriflow needs. Useful comparison for the core pipeline; do not copy all its defaults.
- [`abhishekjnvk/browser-thumbnail-generator`, commit 14a87d5](https://github.com/abhishekjnvk/browser-thumbnail-generator/blob/14a87d57d1b29cec7a8cad31c25f2a876deb5596/src/video-thumbnail.ts) accepts a local File, returns a Blob with dimensions, supports abort, and resets the video/source URL on settlement. Its zero-time path uses `loadeddata`. However, its deadline covers seeking rather than the whole operation; a stalled metadata load or later frame callback can outlive that timer. Borrow cancellation and ownership ideas, but enforce an overall deadline independently.

The smallest useful implementation is one cancellable browser extractor and poster generation in the existing media executor. Defer animated previews, persistent browser caches, frame analysis, and thumbnail editing until there is a product requirement.
