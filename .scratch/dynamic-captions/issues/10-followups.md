### Implementation (2026-11-19)

1. **Fallback-face scale origin: done (vertical).** The shared layout already took `MeasuredWord.boxMiddleEm` (`scaleOriginY` in `caption-block.ts`); the worker fed it the line box of the faces its glyph plan draws the word with, the Studio fed it the requested face's. The Studio now feeds it the line box of the face that draws the word:
   - `packages/caption-fonts/src/fallback-line-boxes.ts` (browser-safe subpath `@narriflow/caption-fonts/fallback-line-boxes`): `captionWordLineBoxEm(text, requestedBox, language, requestedDraws)` repeats the planner's choice per cluster: the requested face when it draws the cluster, else the first fallback face (the cue language's own first, `orderCaptionFallbackFaces`) whose CSS unicode-range holds it, then symbols, then monochrome emoji; a neutral cluster (space, punctuation, digit) stays in the face before it when that face draws it. The result is the tallest Win ascent and deepest Win descent among those faces.
   - `fallback-line-boxes-data.ts` is generated by `packages/caption-fonts/scripts/build-fallback-line-boxes.ts`: per fallback face, Win ascent and descent (`fontFileMetricsEm`), the `unicode-range` from `apps/web/app/caption-script-fonts.css`, and the neutral code points its cmap draws. `fallback-line-boxes.test.ts` holds it to the worker's chain (order, roles, languages), to the font files (metrics and neutral coverage) and to the CSS ranges.
   - `apps/web/app/caption-script-fonts.ts` gets `captionWordBoxMiddleEm(text, face, language)`; the block painter calls it where it called `(ascent - descent) / 2`.
   - Tests: `apps/media/src/caption-block-scale-origin.test.ts` lays out `headline-urdu`, `headline-urdu-punctuation`, `marker-urdu` and `headline-japanese` under `slam` through the worker and through the Studio's feed and asserts every word's `scaleOriginX/Y` and centre agree to 1e-6 px; asserts the old requested-face feed was off by more than 3.5 px; and compares the Studio's line box with the real `CaptionGlyphPlanner` for 27 words in 7 languages and two requested faces. `caption-block-render.test.ts` adds `headline-urdu-slam`, `headline-urdu-punctuation-slam` and `headline-japanese-slam` (the fixture cases with `animation: "slam"`), checked against real libass settled, at +33 ms and +100 ms: baselines within 0.01 px of the model, ink top and bottom within 0.71 px.
   - Pivot difference (px, scale origin above the word centre, Studio minus burn-in), before then after: `headline-urdu` یہ -13.71 to 0, فیصد -35.85 to 0, ہے -13.71 to 0, 50 0 to 0; `headline-urdu-punctuation` قیمت -13.71, 50، -35.85, اب -13.71, کم -13.71, all to 0; `marker-urdu` صرف and ایک and میں -8.91, گھنٹے 0.84, all to 0; `headline-japanese` 今日は 3.46, 3回 7.09, 走った 3.46, all to 0. Full table: `.scratch/dynamic-captions/out/10/pivot-table.md`.
   - Limits: symbols and dingbats (★ ✓ ♥) count as drawn by the requested face, as the pill and plate ink already assumes (`captionFaceDraws`); a face without them (Montserrat, Anton, Oswald) sends them to Noto Sans SC or Symbols 2 in the burn-in, so such a word's pivot differs. An RTL word's U+200F mark face is not modelled; it never grows the line box on the catalog faces.
   - **Open, found by the new libass cases: horizontal pivot.** libass scales an event about its `\pos`, the middle of its `compute_string_bbox` box, which is not the advance centre when a cluster's first glyph is offset (Nastaliq, `bboxCenterEm`). The shared layout and the Studio pivot about the advance centre. Offsets in the fixtures: `فیصد` 44.34 px, `اب` 42.74, `قیمت` 35.41, `صرف` 32.08, `یہ` 3.80; none for Japanese or Latin words, which are within 4.1 px. A word scales away from the pivot by `(scale - 1)` of the offset, so a slam hero at 1.25 drifts about 11 px horizontally for 110 ms. The browser cannot derive that offset without HarfBuzz glyph offsets, so it is not fixed. `caption-block-render.test.ts` therefore unscales the libass ink about the libass pivot (`scaleOriginX` plus the offset); without that the `headline-urdu-slam` hero failed the 4 px edge tolerance at +33 ms (left -3.90, right -4.31). Deferred: needs the offset shipped to the Studio as pinned per-word data or HarfBuzz in the browser; no clip evidence that it is visible.
