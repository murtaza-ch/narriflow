# API extraction implementation plan

Decision-ready plan for `dev`, based on an independent code read on 2026-10-29. This document is the only file produced by this planning task. The owner's single-cutover decision stands. Do not ship an intermediate state or retain a Next backend adapter.

## Decisions to implement

1. Run one Hono-on-Bun API on Railway. Preserve `/api/*`, `/api/v1/*`, `/mcp`, MCP upload paths and discovery paths on the new API origin. Use direct cross-origin browser requests with `NEXT_PUBLIC_API_URL`. Do not add Vercel backend rewrites.
2. Separate `WEB_ORIGIN` from `API_ORIGIN` everywhere. Provider callbacks and machine clients use API; human-facing links use web. Re-register provider endpoints and reconnect development MCP clients in the cutover window.
3. First-party auth uses Clerk session Bearer tokens plus an explicit `X-Workspace-Id` selection hint. Eliminate the active-workspace cookie. Preserve signed-in-only admission for bootstrap, invite acceptance, new Workspace creation and MCP browser continuations.
4. Keep services authoritative. HTTP modules admit, validate, call services and serialize. React Query owns ordinary remote UI state. The Studio Editing Session continues to own drafts, history, revision barriers and cloud convergence.
5. Define ordinary HTTP routes with `createRoute` and `OpenAPIHono`; keep REST v1 as its own authenticated sub-app and document. Export compiled domain types, never one giant application type to browser consumers.

## API modules and contracts

Create this structure. Each domain owns its directory; composition files are edited by the foundation owner only during parallel work.

```text
apps/api/
  package.json, tsconfig.json, tsconfig.build.json, Dockerfile, railway.json, .env.example
  src/index.ts                       Bun.serve and signal/shutdown handling only
  src/app.ts                         createApiApp(deps), mount order, onError/notFound
  src/config.ts                      validated origins, auth, limits and environment
  src/http/{env,errors,request-policy,request-policy-runtime,admission,
            route,limits,cors,logging}.ts
  src/http/{request-policy,admission}.test.ts
  src/domains/<domain>/{routes,contracts,admission,runtime}.ts
  src/domains/<domain>/*.test.ts       adapter tests beside implementations
  src/types/<domain>.ts               type-only export of chained domain app
  src/contracts/public-openapi.json   generated public REST document
  scripts/{generate-openapi,check-route-inventory}.ts
  scripts/run-authenticated-request-policy-db-tests.ts
packages/api-client/
  src/{transport,error,query-client,scope,keys}.ts
  src/<domain>/{client,queries,mutations}.ts
  src/progress/{stream,use-project-progress}.ts
  src/openapi/public-v1.json          generated, browser-safe document export
```

Domains are `session`, `workspace`, `billing`, `ingest`, `projects`, `studio`, `brand`, `publishing`, `automation`, `reviews`, `integrations`, `rest` and `docs-search`. Use additional local files inside a domain when useful, not another global router. Shared request/response Zod schemas belong in `packages/validators/src/api/<domain>.ts`, with explicit subpath exports. Admission metadata stays server-side in each domain's `admission.ts`.

`createApiApp` mounts health/discovery, signature-authenticated webhook adapters, `/api/v1`, `/mcp` and its upload handler before the first-party domain app. Do not put a Clerk session middleware around REST, MCP or webhooks. Signed review, opt-out and public-share requests use their own trust declarations. Unknown first-party handlers without admission declarations fail closed, as `authenticated-request-hono.ts` does today. Unknown paths return JSON 404 rather than a missing-policy 500.

Middleware order:

1. Request ID and bounded structured request logging; install one error handler for ordinary HTTP.
2. Secure response headers and default `Cache-Control: private, no-store`.
3. Host validation for MCP; exact-origin validation/CORS and OPTIONS handling for each route class.
4. Streaming body limit before `.text()`, `.json()`, request clones or webhook parsing. Enforce a bounded header/path length at ingress too.
5. Route-class credential verification. Signature routes retain original bytes; session routes require exactly one Bearer credential before calling Clerk.
6. Authenticated Request Policy in its established order: identity, selected Workspace, capability/status, rate limit, Project concealment/mismatch, input, operation.
7. Service invocation and explicit JSON DTO projection; normalize expected failures with the same request ID.

Use route metadata to attach the admission middleware ahead of OpenAPI's generated validators. Validation must not precede identity/Project admission and disclose foreign resources. Reuse the same schemas for OpenAPI and the policy input stage; avoid two independently maintained validation definitions. A factory must return the chained `.openapi(...).openapi(...)` value, not a variable inferred as blank `OpenAPIHono`. Existing mutation helpers currently return unchained `Hono`, which would erase RPC types if copied verbatim.

Internal routes use session-Bearer security definitions and an internal OpenAPI document available only in development/operator tooling. REST keeps its `nf_` API-key security definition, schemas, scopes, additive v1 contract, `Idempotent-Replayed`, callback rules and existing response codes. Never publish internal endpoints in public v1 docs. MCP JSON-RPC continues through `createNarriflowMcpHttpHandler`; describe/mount its transport without trying to recast tools as REST routes.

Expose `@narriflow/api/types/projects`, `/types/studio`, etc. as declaration-only exports. API-client uses `import type`, instantiates one `hc<DomainRoutes>` per domain and emits declarations with the expensive instantiation already resolved. Export explicit `createProjectsClient` signatures from compiled API-client output, following Hono's `hcWithType` pattern. Both projects use strict TypeScript. Never import the API entry, a service implementation or `typeof createApiApp` into web. Run declaration builds before client/web typechecks, including local watch mode. A type-only dependency must not become a runtime package dependency in a client chunk.

### Docs stay deploy-independent

Today `lib/docs/openapi.ts` imports `lib/rest-api/public-openapi.ts`, which constructs `createRestApi` and transitively imports services. Simply banning imports in pages misses this dependency. Generate the public document from the actual REST app at build time, with no provider calls or credentials, copy it into API-client's `/openapi` export, and import that JSON in docs. CI compares regeneration with the committed artifact. API serves the same document at `/api/v1/openapi.json`; its `servers` uses the configured public API origin. No live API fetch is required to build/render docs, navigation, Markdown, search or OG images. Also fix `(docs)/_components/api/playground.tsx`: it currently overrides the request origin with `window.location.origin`, so updating OpenAPI alone will still send Try It requests to the web host. Its API-key input remains independent of Clerk session transport.

Move `GET /api/docs/search` to API. Export static index records and entry/breadcrumb metadata into `packages/api-client/src/openapi/docs-search-index.json` with `apps/web/scripts/generate-docs-search.ts`, using the Fumadocs build-time MDX pipeline. API retains `createSearchAPI('advanced')` from `fumadocs-core/search/server` and the existing exact-first, typo-fallback, snippet/grouping behavior. Its installed implementation uses framework-neutral Request/Response and zbsearch; test importing that specific entry under Bun. Move the scorer/result projection into `docs-search`, with no import of web's `docsSource` or MDX at API runtime. Generate in this acyclic order: API public OpenAPI artifact, standalone docs-index generation, API/client declaration builds, then app builds. Do not make API build depend on `next build` or web build depend on a running API. Docs UI uses the public API search query factory. Keep `/docs`, Markdown, `llms.txt`, OG rendering and marketing in web.

## Authentication and Workspace selection

Rewrite `packages/auth/src/index.ts`, splitting into `identity.ts`, `workspace.ts`, `clerk.ts` and a small export file. Remove `server-only`, `@clerk/nextjs`, `next`, `next/headers` and React dependencies from this package. Bun must be able to import it directly.

- Create one `createClerkClient({ secretKey, publishableKey })`. Require an explicit `Authorization: Bearer ...`; reject missing/malformed headers even if cookies exist. Call `authenticateRequest(request, { acceptsToken: 'session_token', authorizedParties })`, then `toAuth()` and use the verified Clerk user ID. A nonauthenticated/handshake result becomes JSON 401, never HTML or a redirect. A dependency outage becomes a safe 503, not an apparent sign-out.
- Replace `getCurrentAppUser()` with `getAppUserForClerkIdentity(clerkUserId, clerkClient)`. It retains existing DB lookup, synchronous first-login sync, `needsUserRefresh`, `ensureFirstUseBrandTemplate`, `ensurePersonalWorkspace`, unique-race recovery and confirmed-Clerk-404 email-release logic. Replace `currentUser()` with `client.users.getUser(clerkUserId)` and import backend Clerk types/errors. Webhooks continue calling `syncClerkUserPayload` and `markUserDeletedByClerkId`.
- Replace `getWorkspaceContextForUser(user)` with an explicit `resolveWorkspaceContext(user, requestedWorkspaceId?)`. The hint comes from validated `X-Workspace-Id`, not cookies. Bootstrap checks membership live; missing/removed selection falls back to the personal Workspace and reports `workspaceSelectionChanged`, matching current entry behavior. Subsequent scoped requests require the explicit, currently valid selection; a removed selection returns a safe 409 `workspace_selection_changed` before invoking the operation. Never let an in-flight command fall through into the personal Workspace. Return the effective Workspace ID in bootstrap data and `X-Workspace-Id`; update the browser scope before priming scoped query keys, and discard responses when a request's captured scope no longer matches it. This explicit-selection refusal tightens the old cookie fallback for commands and must have a regression test.
- `setActiveWorkspaceForActor` becomes membership validation returning the selected Workspace DTO. `POST /api/session/workspace-selection` is signed-in-only, so restricted billing in another Workspace cannot prevent switching. Web persists only the selection hint, keyed by Clerk user, in localStorage; other tabs receive a storage event. No authorization decision trusts this storage.
- Provide identity-only `GET /api/session/bootstrap` and Workspace-scoped `GET /api/workspace/bootstrap`. The first provisions the user and lists memberships without enforcing an unrelated Workspace's status. The second returns the admitted actor's safe profile, effective selection, capabilities, usage and billing shell data in one parallel read. It must remain usable for recovery routes under the policy's allowed billing capabilities.
- API `CLERK_AUTHORIZED_PARTIES` explicitly lists full frontend origins: localhost/127.0.0.1 during local development and the deployed dev web origin. No wildcard Vercel previews. Configure a preview origin explicitly before enabling it. This verifies JWT `azp`; it is distinct from API CORS and MCP OAuth resource audience. Future Expo clients must be tested against their actual session-token claims before an allowlist change; do not invent a mobile `azp` now.
- Web obtains tokens through `useAuth().getToken()` at request time. Inject `getToken` into API-client transport, with `credentials: 'omit'`. Never put tokens in React Query keys, URL parameters, logs or persisted caches. A 401 can force one fresh `getToken({ skipCache: true })`; retain the same mutation key and body if retrying an admitted idempotent command. Missing session or another 401 goes through existing auth-entry destination validation.

Move the pure `createAuthenticatedRequestPolicy`, `resolveAuthenticatedProject`, failure translation and relevant tests from `apps/web/lib` to `apps/api/src/http`. Replace `authenticated-request-policy.server.ts` with `request-policy-runtime.ts`. Construct request-local actor promises in Hono context. Do not replace React `cache` with a global Map. Remove `unstable_rethrow` and framework redirect control flow from policy dependencies. Keep `ActorScope.actorUserId` separate from Workspace owner identity. Reuse the outer request ID rather than generating a second one inside the policy.

Carry the inventory test forward as a runtime route-registration comparison in both directions, covering all domain route declarations and explicit trust exceptions. Remove action/page source scanning only when their replacement endpoints and web import restrictions are in place. Keep capability, signed-in, Project mismatch and rate assertions; move the disposable-schema policy test and runner to API, update the root script, and keep MCP/browser/REST command admission parity tests. This is an update to ADR 0009's adapter model, not permission to bypass it.

Web may retain `@clerk/nextjs` `ClerkProvider`, auth UI and a UI-only `proxy.ts` to redirect unsigned page navigations. Strip every API/MCP/discovery matcher and API auth branch. No DB or business decisions in proxy. Client gates remain necessary for changed membership, Workspace mismatch, plan and billing status.

### Cookie-dependent navigations

- OAuth starts become POST JSON commands using session Bearer, returning `{ authorizationUrl }`. `window.location.assign` follows that URL. A normal anchor cannot carry an Authorization header. Keep state persistence, expiry, PKCE and membership rechecks.
- Social callback already resolves identity from `SocialOAuthState.createdByUserId/workspaceId`; preserve it. Zoom currently receives `getActor(c)` through browser admission. Refactor `ZoomService.handleCallback` to consume its hashed, expiring, one-use `ZoomOAuthState`, resolve the actor from that row, verify the stored redirect URI and recheck current membership before and after provider I/O. Declare callback independent trust. Never expect provider navigation to contain a Clerk Bearer token.
- Stripe checkout and portal already return URLs from POST routes. Keep that design; use Bearer for the POST, then navigate. Retain `getOrCreateCheckoutKey`, quote IDs, 202 activation polling and recovery. Their return URLs use W.
- Replace clip `/file` and Workspace export download redirects with JSON Download Grants, then navigate to the short-lived R2 URL without Clerk credentials. The clip and dub download endpoints already return JSON and are the pattern to follow. Review media follows the same approach. Signed URLs need expiry-aware refetch after tab resume; never add Clerk tokens to media URLs.
- Transcript/subtitle text and timeline ZIP endpoints are deliberate downloadable-content exceptions. Use Bearer `fetch`, check status first, then create/revoke a Blob URL for bounded files. Large media goes directly to R2. Preserve content type, file name and `X-Editor-Revision`. Do not turn a video into an in-memory Blob.
- Review `/access` currently sets a 12-hour strict HttpOnly cookie and checks `Origin === request URL origin`. Replace it with JSON `{ sessionToken, expiresAt }` using the existing signed guest-session format and `REVIEW_SESSION_SECRET`; send it as guest Bearer thereafter. Store only in tab sessionStorage keyed to the hashed review token, clear on refusal/expiry, and require access again when expired. Bind the session claims to the requested review token/round, replacing the path separation currently supplied by token-specific cookie names. Compare browser Origin to W's explicit allowlist, never A itself. Preserve passcode/email, guest edit rights, revocation and public-share distinctions. This changes the guest credential's browser exposure and deserves a dedicated XSS/CSP check.

## Web data layer

Add a stable QueryClient under ClerkProvider, preferably around only authenticated app/continuation/review UI rather than every marketing page. API-client accepts injected token and Workspace suppliers; it does not import Clerk or Next. React Query devtools load only in development. Clear all queries and mutation observers on sign-out/user change; cancel and clear old Workspace requests before changing the selected hint. Responses and in-flight mutations capture their original Workspace. A click in Workspace A must never be silently retried in B.

Defaults: `staleTime: 30_000`, `gcTime: 300_000`, stale-query refetch on focus/reconnect, no mutation retries by default. Reads retry at most twice for network/5xx failures; do not retry 400/401/402/403/404/409/422 blindly. Respect bounded `Retry-After` for 429/503. Billing activation and active job status use their existing bounded 2-5 second polling behavior with `staleTime: 0`; configuration/brand lists use 60 seconds. Do not persist query caches containing grants or personal data. Pass AbortSignal through every query function.

Keys start with identity and Workspace: `['nf', clerkUserId, workspaceId, domain, resource, idOrFilters]`. Session bootstrap uses a distinct identity-only key. Canonical filter objects contain only serializable values; date fields cross HTTP as ISO strings, bigints such as event cursors as decimal strings, and Sets/Maps are projected explicitly. Guest data has its own review-token-hash scope. No credential-bearing values in keys. Each domain exports `queryOptions`/`infiniteQueryOptions`, mutation functions and invalidation helpers; pages do not compose URL strings.

Convert every data-dependent page in the 34-file scan into a client data view. Root layout stays a server presentation shell; remove its `validateCoreEnv` and `billingService.validateConfiguration({ surface: 'web' })` calls. App/settings layouts become client gates/shells. Also convert auth-only admissions, search, workspace-unavailable, invite/new-Workspace flows and MCP continuation pages. Keep static metadata wrappers/server UI only when they have no backend imports or data reads. Delete forms' Server Action props and `useFormStatus` assumptions, replacing them with mutation state and client navigation.

Use an aggregate read for each expensive screen, without recreating business logic: Workspace bootstrap; home; projects explorer with folders/pagination/filter facts; project detail; Studio bootstrap; upload configuration/resume; brand overview/detail; calendar/queue; developer settings; automation; performance. API does the current `Promise.all` reads. Do not serialize the 15+ Studio reads into browser waterfalls. Fetch bootstrap and route data concurrently where inputs are already known, prime shared usage/billing/account/brand keys from aggregates, and prefetch route queries on intentional navigation. Paginate transcripts, clips, calendar, exports and search as they are today. Do not fetch a whole transcript in the shell.

Studio bootstrap must preserve retained fonts, scene and b-roll asset references, composition asset refs, source/preview offsets, canonical editor document and QA fixture behavior. The six inline actions become authenticated API endpoints for preview status, automatic/split/screen layout, project censor terms and analytics. QueryClient supplies bootstrap/polling transport; it must not autosave by observing the working editor document. Inject API-client read/write adapters into the existing Studio Editing Session so revision conflicts, cross-tab write ownership and draft durability retain one owner. `studio-editing-session-browser.ts` also has a synchronous close-time `fetch(..., { keepalive: true })`: pass a current in-memory token snapshot obtained while active rather than awaiting Clerk during unload. Respect browser keepalive size limits and preserve the Device Draft when a best-effort close write cannot be sent; cross-origin preflight/unload cannot guarantee delivery. Do not add a cookie fallback. Preserve canonical caption cue derivation.

## Security and retry behavior

## Risks and corrections to the brief

- The brief's 55 actions is stale; there are 62. The 48 refresh figure names files, with 83 calls. A migration checklist based on those older counts will silently miss behavior.
- "JSON only" cannot literally cover SSE, MCP JSON-RPC/OAuth, provider redirects, downloads and docs content. Use JSON control endpoints for first-party clients, with explicit typed stream/download/provider exceptions. Forcing every file into JSON/base64 would waste memory and bandwidth. No mobile implementation is needed to make that distinction.
- `packages/auth` is also the user-sync/provisioning/Workspace module, not a thin Clerk wrapper. Deleting it and adding token verification alone loses personal Workspaces, default templates and email collision protections.
- The active Workspace hint is not Clerk organization identity. This app uses its own memberships. Do not replace it with `orgId`, infer the actor from the owner, or silently run a failed Project mutation in another Workspace.
- Zoom callback is currently a session-admitted route, unlike social callback. Bearer-only navigation requires the stored-state refactor; preserving the current inventory entry will break Zoom.
- `NEXT_PUBLIC_APP_URL` currently determines callbacks, MCP resource/audience, docs server URLs and human links. Changing it globally to A sends emails, consent returns and MCP handoffs to a host with no web UI.
- Review's strict-cookie and same-origin checks will reject direct cross-origin requests unchanged. Review CSP in `next.config.ts` also currently has `connect-src 'self'`; add the exact API origin or review will fail even when CORS passes. Update general report-only CSP too.
