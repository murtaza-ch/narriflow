## Defects and observations

- D1 (low, probably pre-existing): every `/review/*` load logs a CSP violation `Creating a worker from 'blob:...' violates ... script-src (worker-src not set)` from `clerk.browser.js`. The review CSP (`apps/web/next.config.ts`, `source: "/review/:path*"`) has no `worker-src`, and the guest page still loads ClerkProvider/clerk-js and calls the Clerk dev instance even though guests have no Clerk identity. Repro: open any review link in a clean browser, read the console. Fix: add `worker-src 'self' blob:` or keep Clerk off the guest layout.
- D2 (medium, dead end): a Viewer opening `/upload` directly gets "Import could not be loaded ... Try again" (62-viewer-upload.png) because `GET /api/ingest/configuration` returns 403 `capability_denied`. Retry can never succeed; home hero already says "Viewers can watch and download". Suspect the upload screen error mapping in `apps/web/app/(app)/upload` and the API ingest route `apps/api/src/domains/ingest/routes.ts` (`/ingest/configuration`).
- D3 (medium, performance): every authenticated API call takes about 2.3-3.1 s here (`workspace/bootstrap` 2.5 s, `billing/state` 3.1 s, `brand-kit` 2.5 s) while unauthenticated 401s take ~1 ms, and the shell is a serial chain (`session/bootstrap` -> `workspace/bootstrap` -> `billing/state` -> page query), so content appears 5-8 s after navigation; the review POST took ~9 s and checkout ~10 s. Machine load average was ~4.6 with other agents running, but the constant per-call cost suggests per-request auth or workspace resolution against Neon (`resolveWorkspaceContext`, Clerk verification). Spec section on aggregate reads says route data should not wait on the shell; worth a profile before cutover.
- D4 (low): after switching Workspace, `POST /session/workspace-selection` is followed by one `GET /session/bootstrap?workspaceId=<previous>` (old hint) before `workspace/bootstrap` uses the new id. UI ends correct. Suspect the scope update ordering in api-client query-client/runtime.
- D5 (info): malformed `X-Workspace-Id` (`not-a-uuid`) returns 409 `workspace_selection_changed` rather than a 400; acceptable but differs from "validated header".
- D6 (info): after sign-out, localStorage keeps `narriflow:workspace:<userId>` (workspace UUID), `narriflow.checkout.v1:<ws>:pro:annual` (idempotency key) and `narriflow:studio-lease:<project>:<clip>:generation`; no tokens or secrets, in-memory caches are gone.
- D7 (info): superseded Review round still shows "Copy link" and "Open room" that lead to an invalid link.
- E1 (environment): web dev server died unexpectedly; STT failures (row 11); Resend domain unverified so notification and invite emails fail (`notification_delivery_failed` in worker log).
- E2 (data left behind): Round 02 and a guest comment on project `0488562b-...`; Round 01 is now superseded (affects any other agent using the same project); pending Workspace "QA Biz Checkout"; both QA users; projects `19f8dc2d-...` and `0ad087ba-...` in the fresh Workspace.

## Fixes (round 2)

Each fix has a test written first (red, then green). No commits.

- D1 (CSP worker): `apps/web/next.config.ts` review CSP now ends with `worker-src 'self' blob:` (same value as the general CSP). Test: `apps/web/next-config-csp.test.ts`. Clerk still loads on `/review/*` because `ClerkProvider` lives in the root layout (`apps/web/app/layout.tsx`) and the guest page does not use it; left as is on purpose, no layout restructuring.
- D2 (Viewer on `/upload`): `upload-screen.tsx` now sends a `forbidden` configuration failure (`capability_denied`) to `/home?requestFailure=capability_denied`, which is what the old server page's admission redirect did (brand-kit screens use the same path). Pure helper `deniedImportDestination` in `upload/_lib/resume-decision.ts`, tested in `resume-decision.test.ts`.
- D5 (malformed `X-Workspace-Id` is 409, not 400): NOT changed, file is excluded. Cause: `readSelectedMembership` in `packages/auth/src/workspace.ts` returns null for a non-UUID, and `workspace()` in `apps/api/src/http/request-policy-runtime.ts` maps null to `workspaceSelectionChanged()`. Exact fix if wanted: in that `workspace()` step, before `resolveScopedWorkspace`, `if (hint !== undefined && !isWorkspaceId(hint)) throw new AuthenticatedRequestFailure({ code: "invalid_input", category: "validation", status: 400, message: "X-Workspace-Id must be a Workspace id." })` (reuse the existing validation failure code/category used elsewhere in the policy). Note that 409 also triggers the client's reselect recovery, so 400 is only a nicety.
- D6 (sign-out leftovers): new `apps/web/lib/sign-out-storage.ts` `clearSignedInBrowserState(local, session)` removes by prefix `narriflow:workspace:`, `narriflow.checkout.v1:`, `narriflow:studio-lease:` (lease, generation, signal), `narriflow:recent-searches:` from localStorage and `narriflow.settings-return`, `narriflow:campaign-clip-selection:` from sessionStorage. Called from the three sign-out handlers (`account-menu.tsx`, `mobile-nav.tsx`, marketing `account-actions.tsx`) right before `signOut`, so it also runs if navigation cuts the handler short; if Clerk's sign-out fails the advisory hint and checkout key are simply regenerated. Deliberately kept: Studio Device Drafts (IndexedDB), Publishing Drafts (`narriflow:publishing:*`), colour mode, guest review credentials. Test: `apps/web/lib/sign-out-storage.test.ts`.
- D4 (stale-hint `session/bootstrap` after a switch): cause was `selectWorkspaceMutation.onSuccess` invalidating the identity bootstrap; the mounted `SessionGate` refetched with its closure's old hint before React rendered the new one. A switch does not change memberships, so the invalidation was redundant and is removed (`packages/api-client/src/session/mutations.ts`). Accept-invite keeps its invalidation (membership does change). Test in `packages/api-client/src/session/session.test.ts`.
- Not touched (other agent's files): `packages/auth/**`, `apps/api/src/http/**`, `workspace-query-gate.tsx`, `api-provider.tsx`. Not re-verified in a browser; the QA agent should recheck D1, D2 (Viewer), D4 and the post-sign-out `localStorage` listing.
