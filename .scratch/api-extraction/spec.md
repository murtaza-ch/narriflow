# API extraction implementation spec

Final pairing specification, 2026-10-29, branch `dev`. Supersedes `sol-plan.md`. Implementers need this file and their ticket only. Inventory rows copied into tickets record existing behavior; explicit decisions here override inventory proposals. One coordinated cutover, no deployed intermediate state, duplicate backend or Next proxy adapter. No mobile/admin application is in scope.

Use the existing services and validators. Preserve Workspace Actor Scope, plan checks through `hasFeature`/`planLimits` or `requirePlanFeature`/`requireWithinPlanLimit`, shared caption cues and position constants. Services remain exported through `packages/services/src/index.ts`; injected implementation `<concept>.ts`, production wiring `<concept>-runtime.ts`, service implementation `.service.ts`. Structured logs use `console.warn(JSON.stringify({ level, message, ...ctx }))`. Preserve ADR 0002 Studio ownership, ADR 0008 canonical editor persistence, ADR 0009 admission order, ADR 0013 receipts, ADR 0014 transactional events and ADR 0015 publication queue locking. UI uses blue `accent` for interactive state and neutral `brand` for primary buttons/text/surfaces.

## Decisions to implement

1. Run one Hono-on-Bun API on Railway. Preserve `/api/*`, `/api/v1/*`, `/mcp`, MCP upload paths and discovery paths on the new API origin. Use direct cross-origin browser requests with `NEXT_PUBLIC_API_URL`. Do not add Vercel backend rewrites.
2. Separate `WEB_ORIGIN` from `API_ORIGIN` everywhere. Provider callbacks and machine clients use API; human-facing links use web. Re-register the configured Google, TikTok, Stripe and Clerk endpoints and reconnect development MCP clients in the cutover window.
3. First-party auth uses Clerk session Bearer tokens plus an explicit `X-Workspace-Id` selection hint. Eliminate the active-workspace cookie. Preserve signed-in-only admission for bootstrap, invite acceptance, new Workspace creation and MCP browser continuations.
4. Keep services authoritative. HTTP modules admit, validate, call services and serialize. React Query owns ordinary remote UI state. The Studio Editing Session continues to own drafts, history, revision barriers and cloud convergence.
5. Internal routes use returned chained `Hono` registrations with `@hono/zod-validator`; REST v1 alone keeps `createRoute` / `OpenAPIHono`. Export type-only domain routes, never one giant application type. Start without forced declaration precompilation; measure before adding it. Content-only docs search stays in web.

- Inventory file ownership reconciles to 591 TS/TSX/CSS files: 565 domain-listed + shared settings action + five REST files + 20 handler files. Studio's prototype HTML is ancillary. Snapshot JSON/other assets remain assigned with their directories.

Final route counts may change: Zoom callback becomes independent trust, OAuth starts become POST, action reads become GET, and page aggregates add endpoints. ## API modules and contracts

Create this structure. Each domain owns its directory; composition files are edited by the foundation owner only during parallel work.

```text
apps/api/
  package.json, tsconfig.json, tsconfig.build.json, Dockerfile, railway.json, .env.example
  src/index.ts                       Bun.serve and signal/shutdown handling only
  src/app.ts                         createApiApp(deps), mount order, onError/notFound
  src/config.ts                      validated origins, auth, limits and environment
  src/http/{env,errors,request-policy,request-policy-runtime,admission,
            route,limits,cors,logging}.ts
  src/http/{request-policy,admission}.test.ts
  src/domains/<domain>/{routes,contracts,admission,runtime}.ts
  src/domains/<domain>/*.test.ts       adapter tests beside implementations
  src/types/<domain>.ts               type-only export of chained domain app
  scripts/native-smoke.ts             bounded font/passcode/probe/thumbnail image check
  scripts/{generate-openapi,check-route-inventory}.ts
  scripts/run-authenticated-request-policy-db-tests.ts
packages/api-client/
  src/core/{transport,error,query-client,scope,keys}.ts
  src/<domain>/{client,queries,mutations}.ts
  src/progress/{stream,use-project-progress}.ts
  src/openapi/public-v1.json          one generated browser-safe public document
```

Domains are `session`, `workspace`, `billing`, `ingest`, `recipes`, `projects`, `library`, `clips`, `studio`, `exports`, `brand`, `publishing`, `automation`, `reviews`, `developer`, `integrations`, `rest`, `progress` and `platform`. Reserved admin wiring is under `http/admin.ts`, with no admin operations. Use additional local files inside a domain when useful, not another global router. Shared request/response Zod schemas belong in `packages/validators/src/api/<domain>.ts`, with explicit subpath exports. Admission metadata stays server-side in each domain's `admission.ts`.

`createApiApp` mounts health/discovery, signature-authenticated webhook adapters, `/api/v1`, `/mcp` and its upload handler before the first-party domain app. Do not put a Clerk session middleware around REST, MCP or webhooks. Signed review, opt-out and public-share requests use their own trust declarations. Unknown first-party handlers without admission declarations fail closed, as `authenticated-request-hono.ts` does today. Unknown paths return JSON 404 rather than a missing-policy 500.

Middleware order:

1. Request ID and bounded structured request logging; install one error handler for ordinary HTTP.
2. Secure response headers and default `Cache-Control: private, no-store`.
3. Host validation for MCP; exact-origin validation/CORS and OPTIONS handling for each route class.
4. Streaming body limit before `.text()`, `.json()`, request clones or webhook parsing. Reject request URLs over 8 KiB and total request headers over 32 KiB at application ingress, with a bounded safe failure. Confirm Railway ingress accepts this envelope; do not depend on untrusted Content-Length for body bounds.
5. Route-class credential verification. Signature routes retain original bytes; session routes require exactly one Bearer credential before calling Clerk.
6. Authenticated Request Policy in its established order: identity, selected Workspace, capability/status, rate limit, Project concealment/mismatch, input, operation.
7. Service invocation and explicit JSON DTO projection; normalize expected failures with the same request ID.

Internal registration order is `.post(path, admit(declaration), zValidator(..., sharedFailureHook), handler)` and equivalent chained methods. Split admission from input only internally so the existing policy order stays intact. Supply the original declaration's capability, Project parameter, rate key and schemas, never infer capability from HTTP method. Input validation runs after identity/Workspace/capability/rate/Project admission; the handler consumes validated input. Malformed JSON and the validator hook return the common safe error envelope. One shared schema defines each input. A route factory returns the chained value, not a blank `Hono` variable later mutated through helper calls. API-client input/output inference and typed status errors must compile for one real mutation and read per domain.

REST retains `nf_` key admission, scopes, v1 schemas, documented statuses, `Idempotent-Replayed` and callback rules. Its OpenAPI contains only the 31 public operations. MCP continues through `createNarriflowMcpHttpHandler` with JSON-RPC/OAuth envelopes; tools are not recast as REST. No internal OpenAPI document is required.

Expose `@narriflow/api/types/<domain>` as type-only source subpaths, pointing to each chained route type. API-client uses `import type` and one `hc<DomainRoutes>` per domain; both tsconfigs use strict TypeScript. Never import API entry/runtime/service modules as browser values, or infer from `typeof createApiApp`. Ticket 01 captures the median of three warm web typechecks on the unmodified source before extraction. At verification, repeat on the same machine. Add `hcWithType` declaration precompilation only if the median exceeds 1.5 times baseline or a reproducible editor trace demonstrates unacceptable inference latency. The cleanup ticket owns this conditional change and records evidence. Ordinary package builds remain; no unconditional schema/declaration build-before-watch coupling.

### Docs stay deploy-independent

Today `lib/docs/openapi.ts` imports `lib/rest-api/public-openapi.ts`, which constructs `createRestApi` and transitively imports services. Simply banning imports in pages misses this dependency. Generate the public document from the actual REST app at build time, with no provider calls or credentials, copy it into API-client's `/openapi` export, and import that JSON in docs. CI compares regeneration with the committed artifact. API serves the same document at `/api/v1/openapi.json`; its `servers` uses the configured public API origin. No live API fetch is required to build/render docs, navigation, Markdown, search or OG images. Also fix `(docs)/_components/api/playground.tsx`: it currently overrides the request origin with `window.location.origin`, so updating OpenAPI alone will still send Try It requests to the web host. Its API-key input remains independent of Clerk session transport.

Keep `GET /api/docs/search` in web as an explicit content-only handler, alongside docs Markdown, llms text and OG handlers. After replacing `lib/docs/openapi.ts`'s backend import with generated JSON, search imports only Fumadocs/MDX/content helpers. Preserve exact-first/typo fallback, snippets, grouping and its six-result cap; bound query length to 300 characters. There is no API docs-search domain or generated search-index pipeline. The docs playground uses `NEXT_PUBLIC_API_URL` / the document server, never `window.location.origin`; its supplied API key remains separate from Clerk transport. The generated document has deterministic schema content; origin projection is configuration-only and the served artifact must match after normalizing `servers`.

## Authentication and Workspace selection

Rewrite `packages/auth/src/index.ts`, splitting into `identity.ts`, `workspace.ts`, `clerk.ts` and a small export file. Remove `server-only`, `@clerk/nextjs`, `next`, `next/headers` and React dependencies from this package. Bun must be able to import it directly.

- Create one `createClerkClient({ secretKey, publishableKey })`. Require an explicit `Authorization: Bearer ...`; reject missing/malformed headers even if cookies exist. Call `authenticateRequest(request, { acceptsToken: 'session_token', authorizedParties })`, then `toAuth()` and use the verified Clerk user ID. A nonauthenticated/handshake result becomes JSON 401, never HTML or a redirect. A dependency outage becomes a safe 503, not an apparent sign-out.
- Replace `getCurrentAppUser()` with `getAppUserForClerkIdentity(clerkUserId, clerkClient)`. It retains existing DB lookup, synchronous first-login sync, `needsUserRefresh`, `ensureFirstUseBrandTemplate`, `ensurePersonalWorkspace`, unique-race recovery and confirmed-Clerk-404 email-release logic. Replace `currentUser()` with `client.users.getUser(clerkUserId)` and import backend Clerk types/errors. Webhooks continue calling `syncClerkUserPayload` and `markUserDeletedByClerkId`.
- Replace `getWorkspaceContextForUser(user)` with an explicit `resolveWorkspaceContext(user, requestedWorkspaceId?)`. The hint comes from validated `X-Workspace-Id`, not cookies. Bootstrap checks membership live; missing/removed selection falls back to the personal Workspace and reports `workspaceSelectionChanged`, matching current entry behavior. Subsequent scoped requests require the explicit, currently valid selection; a removed selection returns a safe 409 `workspace_selection_changed` before invoking the operation. Never let an in-flight command fall through into the personal Workspace. Return the effective Workspace ID in bootstrap data and `X-Workspace-Id`; update the browser scope before priming scoped query keys, and discard responses when a request's captured scope no longer matches it. This explicit-selection refusal tightens the old cookie fallback for commands and must have a regression test.
- `setActiveWorkspaceForActor` becomes membership validation returning the selected Workspace DTO. `POST /api/session/workspace-selection` is signed-in-only, so restricted billing in another Workspace cannot prevent switching. Web persists only the selection hint, keyed by Clerk user, in localStorage; other tabs receive a storage event. No authorization decision trusts this storage.
- Provide identity-only `GET /api/session/bootstrap` and Workspace-scoped `GET /api/workspace/bootstrap`. The first provisions the user and lists memberships without enforcing an unrelated Workspace's status, and includes safe authContinuation issuer/consent-origin URLs plus capability availability booleans for client navigation. These URLs are validated server configuration, never request-supplied redirect authorities. The second uses `content.view` and returns safe profile, effective selection, capabilities and usage in parallel. Restricted recovery pages use identity bootstrap plus their specifically admitted billing endpoints instead of depending on content bootstrap. Identity bootstrap includes safe membership/status/role facts sufficient to choose recovery without probing blocked content. Do not put one content.view gate around billing or signed-in continuations.
- API `CLERK_AUTHORIZED_PARTIES` explicitly lists full frontend origins: localhost/127.0.0.1 during local development and the deployed dev web origin. No wildcard Vercel previews. Configure a preview origin explicitly before enabling it. This verifies JWT `azp`; it is distinct from API CORS and MCP OAuth resource audience. Future Expo clients must be tested against their actual session-token claims before an allowlist change; do not invent a mobile `azp` now.
- Web obtains tokens through `useAuth().getToken()` at request time. Inject `getToken` into API-client transport, with `credentials: 'omit'`. Never put tokens in React Query keys, URL parameters, logs or persisted caches. A 401 can force one fresh `getToken({ skipCache: true })`; retain the same mutation key and body if retrying an admitted idempotent command. Missing session or another 401 goes through existing auth-entry destination validation.

Move the pure `createAuthenticatedRequestPolicy`, `resolveAuthenticatedProject`, failure translation and relevant tests from `apps/web/lib` to `apps/api/src/http`. Replace `authenticated-request-policy.server.ts` with `request-policy-runtime.ts`. Construct request-local actor promises in Hono context. Do not replace React `cache` with a global Map. Remove `unstable_rethrow` and framework redirect control flow from policy dependencies. Keep `ActorScope.actorUserId` separate from Workspace owner identity. Reuse the outer request ID rather than generating a second one inside the policy.

Carry the inventory test forward as a runtime route-registration comparison in both directions, covering all domain route declarations and explicit trust exceptions. Remove action/page source scanning only when their replacement endpoints and web import restrictions are in place. Keep capability, signed-in, Project mismatch and rate assertions; move the disposable-schema policy test and runner to API, update the root script, and keep MCP/browser/REST command admission parity tests. This is an update to ADR 0009's adapter model, not permission to bypass it.

Web may retain `@clerk/nextjs` `ClerkProvider`, auth UI and a UI-only `proxy.ts` to redirect unsigned page navigations. Strip every API/MCP/discovery matcher and API auth branch. No DB or business decisions in proxy. Client gates remain necessary for changed membership, Workspace mismatch, plan and billing status.

## Web data layer

Add a stable QueryClient under ClerkProvider, preferably around only authenticated app/continuation/review UI rather than every marketing page. ### Invalidation contract

Keys are exactly `['nf', clerkUserId, workspaceId, domain, resource, idOrCanonicalFilters]`. Session keys are `['nf', clerkUserId, 'session', 'bootstrap']`; Workspace bootstrap is Workspace-scoped. Review keys are `['nf-guest', reviewTokenSha256, resource, idOrFilters]`; public shares use a separate hashed-token scope. Signed continuation tokens, access tokens, storage grants and raw secrets never appear in keys or persistent caches. Redact tokens in URLs/logs; continuation queries with signed input use a safe intent digest in the key.

Every domain exports query factories plus mutation/invalidation helpers. Aggregates seed constituent queries only when their data, scope and filters match. Keep tab-specific data out of the shell. ## Stream wire protocol

Keep current named SSE frames `event: workflow.stage.updated` with existing `WorkflowStageUpdatedEvent` JSON, and `event: authorization.revoked` with the existing safe authorization control. Existing sequence lives in `data.seq`; keep the safe integer representation and `sinceSeq` query. No new mandatory SSE `id:` field or browser Last-Event-ID assumption. Emit heartbeat comments every 15 seconds and reauthorize before delivery. Preserve source row identity and bounded `PROJECT_EVENT_ROW_LIMIT`, sequence gap recovery, DB replay and Redis ordering. A revoked stream sends at most one control and closes. Cancel subscribers/timers on disconnect, drain and scope change. A parser failure triggers controlled reconnect/replay, never a full browser reload.

Client reads HTTP failures before entering the parser, shares one subscription per identity+Workspace+Project and refcounts consumers. Capture the last applied sequence, not the last received malformed event. Reconnect with fresh token and jitter, abort previous transport; bounded fallback polling retains progress when Redis/SSE is unavailable. Nonterminal invalidation trails at five seconds; terminal identities invalidate immediately once. Exports and ingest consume the same stream owner; their narrow active polling remains where needed.
