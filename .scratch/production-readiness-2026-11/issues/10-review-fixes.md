## Comments

### Backend (1-13)

All thirteen claims were confirmed in the code. None rejected. No file on the frozen list was touched; item 13 changes validator logic only, no encode args.

1. **Revoked social token. Fixed.** `SocialOAuthError` now carries `providerError`/`providerDescription` from the RFC 6749 body (`readSocialProviderJson`, plus a guard for a 200 with an error body in the four refresh methods). `refreshGrantRefused` marks a dead grant: `invalid_grant` or `invalid_token` on a 4xx, or a 400 `invalid_request` whose description says the token or grant is invalid, expired or revoked (LinkedIn's documented revoked-token answer; X answers a consumed token this way). `TokenExchangeRejected` gained `credentialRefused`; `refreshSocialAccountToken` then releases the claim, reseals the credentials and sets `status: "expired"`, and the caller gets `social_account_expired` ("Reconnect this social account."), which the publication driver already maps to `social_account_reconnect_required`. Everything else that proves nothing rotated (invalid_client, a missing parameter, 429, other 4xx, and every failure on Google: 5xx, transport, a 200 with no token) keeps the account active and rethrows the original provider error as the cause (`social_oauth_http_failed`, real status); status and provider error code are logged as `social_token_refresh_rejected`. Rotating providers keep the unknown-outcome rule (5xx or transport expires via `social_account_refresh_unconfirmed`). Docs: LinkedIn refresh-token page (400 invalid_request), TikTok OAuth error page (invalid_grant). X documents no body for this, so its shape rests on field reports; a bare `invalid_request` without token wording is not treated as dead. Tests in `social-oauth-refresh.db.test.ts`: five dead-grant shapes, the 200-with-error body, seven not-dead shapes. I wrote them before the fix but did not run them against the original code (that file holds uncommitted ticket-06 work); the red evidence is a run with the classifier disabled, where 6 failed, and all pass enabled.
2. **Paid Transcript. Fixed.** `cancelSourceExecutionsWithinTransaction` only fails Transcripts that are not `completed`, unless `discardTranscript` is set. The two source-mismatch paths (validator rejection, `fail` with a mismatch code) set it, since audio that does not match the video is not valid; the existing test at `targeted-workflow-execution.db.test.ts:250` still holds. DB test: audio-first, STT completed, run waiting, video fails, run cancelled and Transcript stays completed. Red before the fix.
3. **Refund need. Fixed.** `closeAdmittedGeneration` returns before the refund when no run was queued, running or waiting. Test: run already completed, video fails, no `sourceRefundNeed`. Red before the fix; the cancelled case still records one.
4. **Respawns while restricted. Fixed.** `recoverAcquisition` asks `acquisitionAuthority` (ingest_job, workflow_run, render_group; other subjects have no domain state). Closed (terminal, other generation, missing) returns null with no bridge call; a non-active Workspace returns `again` with no status call and no respawn row. Only the ingest_job branch has a test; the other two are typed lookups. Tests red before the fix, including budget whole after reactivation.
5. **User delete vs purge. Fixed.** New `project-provider-outcome.ts` (`hasUnresolvedProviderOutcome`: ClipDub unknown or half-written intents; GeneratedMediaJob outcomeUnknown, or reserved with charged attempts) is used by the purge and by `deleteProject`, which refuses with the existing `project_has_active_workflow`. The social-post refusal stays separate. DB test covers the four shapes; red with the call removed. Those rows are immutable by trigger, so the test settles each by deleting it.
6. **`redactFailureText`. Fixed.** The 200 KB hostile inputs took 53 s together before. Now sliced to 2,000 characters before any replace and to 300 at the end; Bearer and Basic run before the key rule; the key rule handles `"access_token":"short"`, `accessToken=abc` and `clientSecret=`. Four tests, red before.
7. **X count. Fixed.** Trailing `.,;:!?'"` and an unbalanced `)` are text; a bare domain on a generic TLD (plus `co`, `tv`) counts 23, any other two-letter TLD only with a path. This approximates twitter-text without copying its TLD list, so a rare TLD still counts by length. Red before.
8. **Awaited cancel. Fixed.** Confirmed with a stream whose cancel never settles (hung at 500 ms). `readBoundedBody` no longer awaits it.
9. **MCP throttle. Fixed.** Both claims confirmed. The socket peer reaches the failed-credential throttle of the MCP and upload entries, and the MCP session authenticator takes the same `CLERK_JWT_KEY` as REST. Test in `mcp.test.ts`.
10. **Scheduler retry instance. Not fixed.** The retry instance id is `nf_retry_<dispatchId>`, so one that finished or errored without acknowledging the wake is reported as `confirmed_existing`, and no new instance can use that id.
