# 05 - Auto title, brand template persistence, Apply-to-all persistence

**What to build:** Newly generated clips carry a title layer from the project's brand title settings; brand templates store those settings; Apply to all clips writes titles on every clip.

**Blocked by:** [01 - Text Layer model and shared layout](01-model-and-layout.md)

**Status:** done

Read `../spec.md` sections 2, 3 and 7. No PostgreSQL gates exist for this (AGENTS.md): review every Postgres-facing change closely and keep database test files typechecking without running them.

## Scope

- Migration: nullable JSON `title` on `BrandTemplate` (`packages/db/prisma`). Do not apply it; the orchestrator applies it at deploy.
- `brand-template.service.ts`: `title` through `toSummary`, `buildSnapshot`, `create`, `update`, `duplicate` (`Prisma.DbNull` for null). `brand-profile.service.ts`: use `brandTemplateService.buildSnapshot` instead of its own `templateSnapshot()` so campaign comparisons do not drift. API routes and the api-client brand domain carry the field; new web treats a missing `title` as the default.
- Seeding (`clip-detection-persistence.ts`): `prepareDetectedClipSeed` carries the brand title settings from `project.brandSnapshot`; `clipStudioEdits` is restructured (it returns early today when there are no emoji picks) and adds the layer with the fixed id `"title"`. Duration clamps to the clip's edited duration after silence and filler cleanup. Rules for who gets a title are in spec section 2. `clip-selection.ts` capsule field from ticket 01 is populated here.
- Apply-to-all (`clip-editor-document-persistence.ts`): a dedicated merge for the `title` branch (it is not a `studioEdits` key and would be dropped silently by the generic merge); `title` and `hookText` on `ClipEditorDocumentStoredState`, `decodePrismaState` and the in-memory test store; skip clips at the layer limit or without usable text; clamp timing per clip; return updated, created and skipped counts; render invalidation and `excludeClipId` as the other branches. Route `POST .../clips/apply-studio-edits` returns the counts; admission declaration unchanged unless the route changes.
- Tests: seed with and without a brand title, off switch, caption-only, blank title, long title cut, short clip clamp, seed hash stable across two runs; Apply-to-all restyle, create, skip at limit, skip without text, clamp, `excludeClipId`; brand template round trip of `title` through summary, snapshot and duplicate.

## Review round 2 (2026-11-27)

Fixes for `review-05.md` (Sol's review with the orchestrator's decisions). Commits 3bb1dea1b (item 1), 2ae14f623 (item 3), 2aa6bcc18 (items 2, 4, 5).

1. **A changed seed during staging no longer strands the run.** In `clip-selection-preparation.ts`, the commit transaction's hash check is now `requireStagedCapsuleCurrent(staged, current)`, which throws `WorkflowFailure("selection_input_changed", "retryable")` instead of returning `superseded`. The other `superseded` returns (no current parent, run not `queued`/`waiting`) are unchanged, and windows another attempt already committed are still reused (`register`).
   - The driver (`clip-selection-control.ts` `runParent`, called from `apps/api/src/workflows/domain-runtime.ts`) does not catch it, so the Workflow command step fails and retries (`WORKFLOW_COMMAND_STEP`: 10 retries, 6 s linear backoff). The next attempt re-reads the run, tags again under the accepted spend policy, and stages the current capsule. If the inputs keep changing past the retry budget, the step ends as it does for any other retryable selection failure (for example `selection_not_prepared`).
   - Staged objects and cleanup obligations: the throw happens inside the third transaction before any write in it (before `lockPlannedExecutionObject` and the `nextAttemptAt` push), so that transaction rolls back with nothing changed. The input and empty-result objects were written to storage after the second transaction admitted their `selection_execution`/`execution_input` cleanup obligations with `notBefore = now + 12 min`. Those obligations stay as they are. No `ClipSelectionWindow` row ever references these keys (each attempt uses a fresh random key segment), so `selectionExecutionObjectRetainUntil` holds nothing and media cleanup deletes the objects once `notBefore` passes. The retry admits its own obligations for its own keys.
   - Test: `packages/services/src/clip-selection-staged-capsule.test.ts` (a brand title change gives a different capsule hash, and that mismatch throws the retryable failure; an equal hash passes). The transaction path itself is only covered by `clip-selection-preparation.db.test.ts`, which is not run.
2. **An unreadable clip no longer aborts a project-wide change.** The Prisma bulk read returns a row that fails to decode (a `ClipEditorDocumentPersistenceError` or `UnsafeUrlError` from the document, `editorOriginal` or the project transcript) as `{ unreadable: true, clipId, revision }`. Persistence also treats a state that fails canonicalization this way. These clips are skipped for every project-selection intent (patches and caption preset), their revisions stay in the commit guard, the result carries `unreadable: n` (absent when 0), and a title request counts them as `skipped`. Each one is recorded in diagnostics with outcome `rejected`. `readProjectSelection` (emoji suggestion targets) leaves them out.
   - Tests: "Apply to all clips: an unreadable clip" (persistence path with the in-memory store, and `prismaClipEditorDocumentStore.readProjectSelection` through an injected fake client). The old test "a malformed project target aborts before any target changes" asserted the behaviour this decision reverses; it now asserts the malformed clip is skipped and the valid one changes.
3. **An unreadable brand caption preset falls back.** `runCaptionStyle` uses `safeParse`; on failure the run resolves as with no template preset. Test: "an unreadable brand snapshot" in `clip-detection-title.test.ts` (the old `.parse` throws on that input).
4. **Fitting timing is kept.** `clampTitleTiming` keeps the patch's interval when `start < duration` and the end is open or `<= duration`. Otherwise the end comes in to the duration and the start is capped at `end - 0.5` (or `duration - 0.5` when open, never below 0), so the end is after the start by construction and the null fallback is gone. Test: "an interval that fits the clip is kept" (9.8-10.0 stays on a 10 s clip; 9.8-12 becomes 9.5-10; 15-open becomes 9.5-open).
5. **Counts come from the request.** The route answers `{ updated, field: "title", title: { restyled, created, skipped } }` whenever any requested patch is a title, zeros included. Persistence always returns title counts for a title request, and `restyled` counts only clips whose title layer changed (compared after canonicalization). Tests: "a title request that touches no clip still answers with zero counts", "a background change beside an unchanged title is not counted as restyled" (services), and "apply studio edits to all clips" in `apps/api/src/domains/clips/routes.test.ts`.

SQL-facing paths this round: `prismaClipEditorDocumentStore.readProjectSelection` (same query; only the per-row decode now catches), and the selection commit transaction (it now rolls back instead of committing an empty read-only transaction on a hash mismatch). No query text, migration or write changed.
