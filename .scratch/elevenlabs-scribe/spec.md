# Spec: ElevenLabs Scribe v2 replaces AssemblyAI, and transcripts/captions work in every language

**Branch:** `feat/elevenlabs-scribe` · **Owner decisions:** full switch, async + webhooks per ElevenLabs docs, **keep the current language picker (Auto default); no re-transcribe action** (owner 2026-10-30), fonts for every script, Roman-script captions later as a separate feature, implementation by Sonnet (high), review by Sol.

## Why

Measured 2026-10-29/30 (evidence: `/tmp/urdu-debug`, `/tmp/stt-bench/RESULTS.md`, memory `urdu-stt-root-cause-2026-10-29`):

- AssemblyAI auto-detect labelled an Urdu video Hindi, routed it to `universal-3-5-pro`, which mixed Devanagari/Urdu script and dropped 226 s of speech. Universal-2 writes Punjabi/Bengali in Devanagari.
- FLEURS, 16 languages, language set: Scribe v2 lower error in 13/16 (Arabic 3.6% vs 22.1%, Bengali 13.6% vs 100%, English 5.3% vs 8.4%), ties Spanish/Japanese. Word timings fine on both.
- Scribe's own auto mode on full files can mix scripts (Urdu → 1,786 Devanagari / 1,275 Arabic-script words) and silently drop speech (Tamil: 66 words for 288 s, language detected at 0.9999). Pinned to the right language it was clean in every case.
- 68-min English podcast: 13,054 words, 1 gap, 2 clean speakers, 69 s to transcribe; source read straight from a presigned R2 URL.
- Price is equal (~$0.22/h incl. diarization).

Pre-production policy applies: AssemblyAI code is deleted in this change; stored transcripts stay (the normalized model is provider-neutral).

## Behaviour after this change

1. **Recognition** — every transcript comes from `scribe_v2` (`diarize=true`, `timestamps_granularity=word`, `tag_audio_events=false`, `language_code` always set when known).
2. **Language** — the existing language picker stays everywhere it is today (import picker, generation setup, recipe, REST `/api/v1` and MCP `languageCode`), defaulting to **Auto-detect**; its option list becomes Scribe v2's languages.
   - Chosen → sent to Scribe as-is (`language_code`), no probe.
   - Auto → the worker first runs a **language probe**: ~60 s of audio sampled from several points (whole file when short), one synchronous Scribe call, no diarization. The detected language is pinned for the full transcription. If the probe fails, hears no speech, or detects a language outside the registry, the full run is unpinned (Scribe auto).
   - Works identically for uploads, YouTube, Drive, Zoom, RSS, etc. — never uses import metadata (YouTube tagged the Urdu video `hi`).
   - Script-variant languages (Hindi/Urdu, Serbian Cyrillic/Latin, …) cannot be decided from audio: on Auto they get the probe's detection, consistently in one script; users who need the other script pick it in the picker. No region special-casing.
3. **Async delivery** — the worker submits with `webhook=true` and `webhook_metadata={workflowRunId, attemptId}`, stores `transcription_id` as `Transcript.providerJobId`, and releases the run to `waiting` (existing machinery). Completion:
   - **Webhook doorbell**: `POST /api/webhooks/elevenlabs` verifies `elevenlabs-signature` (HMAC, `ELEVENLABS_WEBHOOK_SECRET`) and, for `speech_to_text_transcription`, makes the matching waiting run due now. For `webhook_error`, it fails the attempt with the provider's message (retryable per normal attempt policy). Unknown event types → 200 no-op. The API never parses or stores the transcript itself.
   - **Worker retrieves**: the existing `stt_results` loop GETs `/v1/speech-to-text/transcripts/{transcription_id}` — `404 transcript_not_found` = not ready; `200` = finalize (store raw JSON, normalize, `completeTranscript`). With no webhook the loop still completes the run on its slower backstop cadence. One completion path; idempotent by `providerJobId` fencing that already exists.
   - Webhook route body limit must accept multi-MB payloads (a 68-min transcript was 3 MB; 10 h ≈ 45 MB). Raise only for this route.
4. **Input** — prefer `source_url` = presigned R2 source URL (fast path, no download). Fall back to ffmpeg-extracted mono audio uploaded as `file` (existing fallback path) when presigning fails or the source exceeds the remote-URL size the docs guarantee.
5. **Normalization** (`packages/services`) — keep `type:"word"` tokens; group consecutive words by `speaker_id` into turns (missing `speaker_id` → one speaker); run the existing sentence splitter. **No-space scripts** (Han, Hiragana/Katakana, Thai, Lao, Khmer, Myanmar, Tibetan): merge Scribe's per-character tokens into lexical words with `Intl.Segmenter(language, {granularity:"word"})`, timing = first.start→last.end. Language codes normalized to the registry's canonical code before storage. Normalization errors are permanent (fixes today's re-poll-until-timeout quirk).
6. **Language registry** (`packages/validators/src/language.ts`) — Scribe v2's published list (~99). Canonical code = ISO 639-1 where one exists, else ISO 639-3 (`yue`, `fil`, `ceb`, `ast`, …); a provider map to the 639-3 code Scribe returns. Each entry carries its label, script and text direction. The web picker becomes one flat list with Auto first (no accuracy bands, no model groups). Stored codes not in the new registry (`en_us`, `en_uk`, `en_au` → `en`, `jw` → `jv`, unsupported → null/Auto) are migrated in `Project.languageCode`, `Recipe.languageCode`, generation-context/recipe JSON, `Transcript.languageCode`, and any DB check constraint.
7. **Text across scripts** (one shared helper in `packages/validators`):
   - `joinTranscriptWords(words)` — no space between two words whose boundary characters are both in no-space scripts or are CJK punctuation; every word-join site uses it (utterance-split, clip-timing `rebuildText`, composition-plan cue text, subtitle/TXT exports, editor-document, Studio transcript panel, caption ASS + Studio caption engine, titles, auto-censor display).
   - Sentence terminals cover `。！？．` `؟` `۔` `।` `॥` `።` `။` `։` `;`(U+037E) and closing quotes/brackets in those scripts.
   - Caption edge-punctuation set and locale-aware casing (`toLocaleUpperCase(lang)`; skip casing for scripts without case; never produce Georgian Mtavruli the fonts lack).
   - Clip slice keeps zero-duration words (`clip-timing.ts` `MIN_WORD_DURATION_SEC` filter applies only to edge slivers created by clamping).
8. **Fonts for every script** — vendor Noto faces in `packages/caption-fonts` for Armenian, Bengali (+Assamese), Gurmukhi, Gujarati, Oriya, Tamil, Telugu, Kannada, Malayalam, Sinhala, Lao, Khmer, Myanmar, Georgian, Ethiopic, plus language-aware faces: Noto Nastaliq Urdu for `ur`, Noto Sans JP for `ja`, Noto Sans TC for `yue`/Traditional. Regenerate glyph-coverage data; the glyph planner takes the caption language so language-aware faces win for their language. `check-render-environment` probes one glyph per script. Studio preview loads the same faces (`@font-face` with `unicode-range`, lazily) so preview == export.
9. **Right-to-left** — cue direction from its first strong character. Studio: `dir`/`lang` on the cue, word order and karaoke sweep correct for RTL. Export: libass paragraph direction correct for RTL (Encoding −1 or explicit), active-word/pill/emoji geometry mirrored for RTL cues.
10. **Cleanup** — remove AssemblyAI code, constants, env vars, error codes (renamed `elevenlabs_*`), copy, README/runbook/env examples; `env-check` prefix `ELEVENLABS_`; worker reads `ELEVENLABS_API_KEY`, API reads `ELEVENLABS_WEBHOOK_SECRET`. ADR 0018 records the provider decision and the probe-then-pin language policy.

## Out of scope (owner decided)

- Roman-script captions (Roman Urdu / Hinglish) — later, separate feature.
- Diarization tuning (`diarization_threshold`), keyterms.

## Decisions after Sol's spec review (2026-10-30) — these override the sections above

Review: [sol-spec-review.md](sol-spec-review.md). Benchmark: [benchmark-fleurs.md](benchmark-fleurs.md). Vendor matrix: [sol-scribe-vs-assemblyai.md](sol-scribe-vs-assemblyai.md).

- **D1 Durable submission.** Before the full POST the worker records provider-wait intent on the current attempt through the lifecycle (run `waiting`, `providerJobId` null, submission deadline). On 202 it records `request_id` and `transcription_id` (`providerJobId` = `transcription_id`, never the request id). Recording acceptance tolerates an already-terminal attempt and never resurrects it. A waiting run with no accepted id past its deadline fails the attempt (retryable → the next attempt resubmits; duplicate vendor cost accepted and stated in ADR 0018). Timed-out POSTs are not blindly retried within the attempt.
- **D2 One finalizer, two triggers.** A service-owned `finalizeScribeTranscript` (packages/services) normalizes, stores raw JSON under an attempt-and-provider-specific key, and completes the transcript fenced by run + attempt (+ provider id when known). The signed webhook calls it with the callback payload (correlated by `webhook_metadata` {workflowRunId, attemptId} and `data.request_id`/`transcription_id`); the worker's GET recovery calls the same function. Duplicate, stale, cancelled or terminal deliveries → acknowledged no-op. `webhook_error` (top-level `request_id`, `error_message`, `webhook_metadata`) fails the matching attempt with a classified code. Return 2xx after durable handling, 5xx on temporary persistence failure. Do not loosen `ownedAttemptWhere` globally; completion from `waiting` is already lease-free.
- **D3 Webhook config.** Worker sends `webhook=true`, `webhook_id=ELEVENLABS_WEBHOOK_ID` (dev: `a8617871106b4284b0fda2c9e0225c4a`). Missing key/webhook id or `no_webhooks_configured` → permanent, visible failure; no synchronous fallback for the main transcription. Owner enables webhook retries in the dashboard.
- **D4 Signature.** Header `elevenlabs-signature: t=<seconds>,v0=<hex>`; HMAC-SHA256 over `<t>.<raw body bytes>` with the secret string; 30-minute age window with bounded future skew; constant-time compare. Tests: valid, Unicode body, whitespace mutation, missing/malformed header, bad digest, expired, future, duplicate delivery.
- **D5 Body size.** New dedicated body-limit class for this route only (target 128 MiB, tested), mutually exclusive with the 1 MiB webhook class; raise Bun's native cap accordingly; ingress tests with Content-Length and chunked bodies. Admission declares `POST /webhooks/elevenlabs` with `trust:"provider_signature"`.
- **D6 Probe.** Only when no language was chosen and probed source duration ≥ 60 s. Three non-overlapping 20 s windows centred at 20%/50%/80%, read by FFmpeg range requests from the presigned URL (no full download), concatenated mono 16 kHz, one synchronous Scribe call (no diarization). Pin only when `language_probability ≥ 0.80` AND the probe returned ≥ 15 words AND the code maps into the registry; otherwise unpinned. Thresholds are heuristics recorded in code with this rationale. Probe failure never fails the run. Usage/credits unchanged (ADR 0012).
- **D7 CJK/no-space tokens.** Keep provider tokens (per-character for zh/ja) as timed words — no merging. Add optional `TranscriptWord.spaceBefore?: boolean` set by the normalizer from Scribe spacing tokens. `joinTranscriptWords` uses `spaceBefore` when present, else a script rule (no space when both boundary chars are Han/Hiragana/Katakana/Thai/Lao/Khmer/Myanmar or CJK punctuation). Caption cue grouping stays one deterministic policy in composition-plan for Studio, burn-in and subtitle exports: a run of no-space-script tokens fills a cue by a character budget (`wordsPerCue × 2` characters) instead of token count; no Intl.Segmenter in cue grouping (browser vs Bun ICU differ).
- **D8 Catalog.** Scribe's documented list + Yoruba (API accepts `yo`→`yor`, verified). Canonical code = ISO 639-1 when it exists, else 639-3; explicit forward (canonical→provider 639-3) and reverse (provider→canonical, also accepting `cmn`) maps. Input catalog separate from detection normalization. `tl`→`fil` (API returns `fil` for `tl`, verified), `jw`→`jv`, `en_us/en_uk/en_au`→`en`; other retired codes → null (Auto) for inputs; transcript results keep a recognizable normalized code.
- **D9 Migration.** New forward migration (never edit `20261024210000_recipes`; there is no language CHECK constraint). Field-specific transforms for `Project.languageCode`, `Recipe.languageCode`, `Transcript.languageCode` (incl. 639-3 values), `UploadSession.generationSettings.languageCode`, and language-bearing paths in `IngestJob.payload` (incl. `generationContext`). Pending upload acceptances whose fingerprint covers the language are expired/reset (pre-production). Historical `provider="assemblyai"` rows and raw JSON stay as-is.
- **D10 Effective language.** Requested language (`Project.languageCode`, nullable) stays separate from detected language (`Transcript.languageCode`). Captions/fonts/casing/direction use the effective language = transcript language ?? requested; it must flow through the transcript → editor → composition caption layer contract.
- **D11 Fonts.** Pinned Noto families with version, checksum, OFL license and ASS/browser family names in a manifest: Armenian, Bengali, Gurmukhi, Gujarati, Oriya, Tamil, Telugu, Kannada, Malayalam, Sinhala, Lao, Khmer, Myanmar, Georgian, Ethiopic, Nastaliq Urdu (latest upstream release), Noto Sans JP, Noto Sans TC. Locale precedence for script runs (ja→JP, yue→TC, zh→SC, ur→Nastaliq for Arabic-script runs) identical in worker and browser, without overriding a deliberate custom brand font that covers the glyphs. Shaping specimens per script (conjuncts, marks, Urdu joining, Pashto/Sindhi letters). Studio loads faces lazily (`preload:false`, `unicode-range`; static WOFF2 subsets keeping shaping tables if size requires). Mongolian = Cyrillic only; vertical script out of scope.
- **D12 Geometry and RTL.** Per-word geometry must exist for fallback-face text too: measure contiguous same-face runs with HarfBuzz shaping (the engine libass uses) and derive visual word boxes in bidi visual order; complex scripts take no letter spacing; Nastaliq ascent/descent drive line metrics. Cue base direction from the first strong character; mixed Latin/number runs isolated. libass `Encoding -1`; karaoke/active-word sweep verified on the pinned libass for RTL (animated clip fallback if `\kf` sweeps the wrong way). Studio mirrors the same direction, order and degradation contract. If geometry is genuinely unavailable for a run, the same typed degradation applies in both Studio and export.
- **D13 Errors.** Classify nested `detail` objects: missing config / 401 / 403 / quota exhausted / invalid media / invalid language / malformed normalization → permanent; network / 408 / 429 / concurrency / 5xx → retryable (bounded); only `404 detail.code=transcript_not_found` = pending until deadline. Renamed `elevenlabs_*` codes in processing-retry-policy + user copy in error-messages (never raw provider text).
- **D14 Runtime.** Worker Dockerfile pins Bun 1.3.6 while local is 1.4.2 — tests that depend on ICU behaviour run under the worker image's Bun or avoid ICU-dependent assertions. Drain/reset pending AssemblyAI waiting runs before the new worker runs against shared dev data.
