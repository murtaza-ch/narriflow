# Scribe spec review

**Verdict: request changes before implementation.** The full provider switch is justified by the supplied evidence and owner decision. The spec is not ready for independent implementers: its submission race is unresolved, pinning is unconditional despite weak evidence, lexical merging changes editing semantics, and RTL/font parity lacks a geometry contract.

Reviewed `.scratch/elevenlabs-scribe/spec.md`, repository `AGENTS.md`, ADR index and relevant lifecycle/usage ADRs, the three earlier Sol reports, benchmark results, and current code. Today's supplied measurements supersede older protocol uncertainty. Review only: no repository edits, provider jobs, database writes, or application startup.

## 1. Async/webhooks: sound direction, incomplete correctness contract [P1]

Spec lines 25–28 are correct **after** `waitForProvider` commits. The current command atomically saves the provider ID and releases the run, but the POST happens first (`apps/worker/src/tasks/transcribe.ts:629–639`). A callback can arrive while the run is still `running`; a worker crash after the 202 can leave no saved transcription ID. A doorbell restricted to matching waiting runs discards that callback. The GET backstop cannot recover an ID it never stored. Existing completion fencing does not solve this external-side-effect gap.

Also, API finalization is not currently a drop-in alternative: `ownedAttemptWhere` requires the executing worker's lease owner for `running` runs (`packages/services/src/workflow-run-lifecycle.ts:412–428`). An API instance cannot simply call `completeTranscript` for that worker's running claim.

**Smallest design I would approve:**

1. Before the full POST, persist the current Workflow Attempt's provider-wait intent through the lifecycle, including attempt identity and submission deadline. Reuse `waiting`; specify recovery for a waiting submission with no accepted ID. Today's `claimDueWaitingTranscripts` excludes null IDs, so its timeout does not cover that state. Keep the synchronous probe under the worker's ordinary renewable lease.
2. Submit once with current run/attempt metadata. Persist `request_id` separately from `transcription_id`; the latter remains `providerJobId`. Never substitute the request ID into the GET URL. Recording acceptance must tolerate an already completed/failed attempt and must never resurrect it.
3. Let the signed callback call a **service-owned shared finalizer** using its full payload. The worker's GET recovery calls that same finalizer. This removes the unnecessary extra GET on normal completion and recovers a lost 202 response when the callback arrives. Keep normalization, raw storage, completion and failure policy out of the route handler.
4. Fence every callback against the current run, attempt and any accepted provider correlation. Treat duplicate, stale, cancelled and terminal deliveries as acknowledged no-ops. Do not loosen `ownedAttemptWhere` globally. If callback processing cannot fit the provider's response deadline, durably save a small attempt-scoped receipt pointing to the raw payload before acknowledging; no general event bus.

A crash with **both** a lost acceptance response and lost callback cannot be recovered exactly once without provider idempotency or another lookup contract. State the bounded timeout/new-attempt resubmission policy and possible duplicate vendor cost. Do not copy today's blind POST retry wrapper or catch-all audio fallback. Retries of GET are safe; a timed-out POST may already be paid work.

If the doorbell is retained, it must gain equivalent early-delivery persistence/recovery or explicitly accept that bounded resubmission. “Already idempotent” is insufficient. Raw object keys must include attempt/provider identity too, so a stale finalizer cannot overwrite another attempt's diagnostic JSON before its DB fence rejects it.

The error event has **top-level** `request_id`, `error_message`, and `webhook_metadata`, without `data` or a guaranteed transcription ID. Success correlation lives under `data`. Parse both envelopes. Enable webhook retries explicitly in workspace setup; they are off by default. Require retained results for GET recovery, not `enable_logging=false`. Return 2xx after durable handling, 5xx for temporary persistence failure, and acknowledge stale deliveries. [STT webhook contract](https://elevenlabs.io/docs/eleven-api/guides/how-to/speech-to-text/batch/webhooks).

Signature acceptance needs exact raw bytes, header `t=<seconds>,v0=<hex>`, and HMAC-SHA256 over `<timestamp>.<raw body>` using the secret string. Validate malformed/expired/future timestamps with bounded clock skew and compare validated equal-length digests in constant time. Test Unicode bytes, whitespace mutation, missing header, malformed digest and timestamp, replay age, and duplicate delivery. A single happy SDK vector is inadequate. The current SDK uses a 30-minute age window. [Official verifier implementation](https://github.com/elevenlabs/elevenlabs-js/blob/main/src/wrapper/webhooks.ts).

Configure a specific `webhook_id` as well as its secret; otherwise jobs go to every configured STT webhook. Missing/disabled/misconfigured webhook setup must fail visibly, including measured `no_webhooks_configured`, rather than fall back to synchronous main transcription. [Submit contract](https://elevenlabs.io/docs/api-reference/speech-to-text/convert).

## 2. Probe then pin: conditional heuristic, not a proven general repair [P1]

Spec lines 11 and 22 overstate the result. There is evidence that explicit language fixes the demonstrated full-file Tamil/Urdu failures. There is **no supplied trial of the proposed multi-window probe pipeline**, nor evidence it prevents equivalent failures across the catalog. Tamil auto already identified `tam` at 0.9999. Confidence cannot certify lexical coverage. Pinned Tamil still has 41.3% WER; “clean in every case” must mean a specifically measured improvement, not correct recognition everywhere. The benchmark also contains languages where automatic recognition scores better than pinned recognition.

Keep explicit user choice authoritative. Keep auto as the default. Do not derive hints from import metadata, account location or script guessed from a partial result.

Specify deterministic, non-overlapping windows, such as three 20-second windows spread through the source and clamped to duration. Handle short sources, missing audio, cancellation and corrupt media. Avoid relying on the first minute: music/silent intros are common. One concatenated probe returns one dominant-language judgment; it does **not** establish agreement among windows or detect multilingual content. Do not invent a consensus check without separate observations.

**Yes, low-confidence or insufficient-speech probes should leave the full run unpinned.** Define a conservative confidence/speech-evidence predicate and label its thresholds as heuristics to validate. Reject empty/unsupported/malformed probe results. High confidence alone remains insufficient, and an empty probe is not proof the whole source has no speech. A wrong dominant-language hint can bias code-switched or changing-language material; pinning is not guaranteed to preserve those portions. Test bilingual content directly. A source language also cannot express Serbian script preference, and Hindi/Urdu have acoustically ambiguous passages.

Budget the extra audio read and synchronous recognition. A 60-second probe adds one minute of provider work; whole-file probes on short files can double STT work. Either accept that explicitly or skip probing below a stated duration. The 69-second full-file result excludes probing and extraction. Specify FFmpeg range reads/remote seeks where supported, using Worker Process Module cancellation and scratch cleanup; a full 591 MB download for a probe would erase much of the URL fast path's benefit.

Acceptance needs saved probe output plus pinned-vs-auto results for intro music, silence, short speech, ordinary English, unrelated scripts and code-switching. This can remain a small evaluation, not a new language-routing framework.

## 3. CJK normalization: preserve character timings first [P1]

Spec line 30 turns provider tokens into new lexical edit units. `Intl.Segmenter` boundaries are dictionary-dependent; first-start/last-end preserves a merged span's exterior but loses the internal character timings. Karaoke, deletion, trimming and word replacement then become coarser. Never merge across speakers, sentence terminals or substantial gaps, and never interpolate timings when a dictionary boundary falls inside an existing multi-character token.

Local read-only check: **Bun 1.4.2 / ICU 78.1** supports the tested locales and dictionary-segments Chinese, Japanese and Thai. It produced `今天|天气|很好|。` and `東京|都|に|行き|ます|。`; Khmer/Myanmar samples were coarser. This does not certify deployed behavior: `apps/worker/Dockerfile` pins **Bun 1.3.6**. Test actual Linux runtime output, not merely `supportedLocalesOf`.

**Prefer keeping per-character CJK words in this replacement.** Let the existing composition cue policy group their timed units by `wordsPerCue`; document that this is a token count for these scripts and test readability. Keep one grouping policy for Studio, burn-in and subtitle exports. Add lexical grouping only if editing usability earns the timing tradeoff. If retained now, normalization must map UTF-16 offsets back to original token spans, preserve all punctuation, respect explicit spaces, and freeze the resulting word identities once.

The proposed script-only joiner is lossy for Thai/Lao/Khmer/Myanmar phrase spaces, Latin insertions, digits and punctuation. Preserve explicit provider separator information without treating spacing tokens as timed lexical words; define the smallest separator field/helper contract before parallel work. Do not throw away separators and pretend a Unicode regex can reconstruct them. Cover `2026年`, `「OpenAI」`, Thai phrase spacing and mixed-script text. Tibetan does not share CJK token/spacing rules and is absent from the reviewed Scribe list.

The clipping fix also needs a half-open boundary rule for zero-duration words: include a token at `t` when `start <= t < end`, retain genuine short interior words, and discard only actual clamped edge slivers. Audit cue/render validity too; preserving a zero-duration token in JSON alone does not make it visible.

Preserve abbreviation/decimal handling when expanding sentence terminals. Greek U+037E and ASCII semicolon need distinct handling or language context; an English semicolon must not become an unconditional sentence end. Add Turkish casing and mixed-script punctuation fixtures.

## 4. Codes and data migration: approve canonical scheme, complete the inventory [P1]

ISO 639-1 where available, otherwise 639-3, is sensible. Use explicit forward/reverse provider maps, not prefix slicing. Provider mapping belongs at the adapter boundary. Separate the supported **input catalog** from detection-result normalization and retain original provider language in raw JSON.

The explicit published list currently contains **100 entries**, while a separate accuracy band mentions `yor`. Freeze an enumerated, sourced catalog and resolve that discrepancy; do not ship an approximate “99” constant. Absent languages must be removed from picker/API promises deliberately. [Scribe catalog](https://elevenlabs.io/docs/overview/capabilities/speech-to-text).

Migration needs more than the examples at line 31:

- `en_us/en_uk/en_au -> en`, `jw -> jv`, and an explicit **`tl -> fil` decision** for the former Tagalog selection. Normalize stored `eng/urd/jpn/...` transcript results too. Do not erase recognizable old codes merely because they are not current input choices.
- Cover `Project.languageCode`, `Recipe.languageCode`, `Transcript.languageCode`, `UploadSession.generationSettings.languageCode`, and the actual language-bearing paths in `IngestJob.payload`, including `generationContext`. Inspect command/handoff JSON that can be replayed. Do field-specific transforms, not a recursive replacement of arbitrary strings.
- Upload Sessions bind immutable input fingerprints. Migrating accepted settings without considering that fingerprint can break replay. For pre-production, explicitly expire/reset affected pending acceptance data or update it under the owning contract. Do not add legacy parsers.
- Historical raw provider JSON and completed `provider="assemblyai"` attribution remain historical facts. Do not relabel them ElevenLabs or require reading old raw JSON through a new adapter.

**Correction to the challenge premise:** `20261024210000_recipes/migration.sql:42` contains an inline `CASE ... IN (...)` migration allow-list, not a persistent language CHECK constraint. I found no language CHECK in the migrations. Add a new forward migration for current rows; do not edit an already-applied recipe migration or invent a constraint-removal task. Verify both upgraded and fresh schemas.

Language must reach captions through the transcript/editor/composition contract. Current composition caption layers carry no language. Auto projects retain `Project.languageCode=null`; using that field for font choice/casing would lose detected Urdu/Japanese. Keep requested language separate from detected/effective language, and make script/direction metadata advisory for languages with multiple scripts.

## 5. Fonts and RTL: missing assets are necessary, geometry is the harder blocker [P1]

The proposed Indic/Armenian/Georgian/Ethiopic additions are appropriate. Freeze font versions, checksums, licenses, internal ASS family names, browser family names, ranges and metrics in the asset contract. One glyph per script proves almost nothing about shaping: include conjuncts, combining marks, Urdu joining, Pashto/Sindhi letters, and Latin/Cyrillic extensions used by the supported catalog.

Noto Nastaliq Urdu is an appropriate Urdu face, but measure its actual ascent/descent and ink extents. Baseline, line gap, fit-to-frame, pill height and emoji top must account for fallback faces. Current `caption-ass.ts:407/453` uses requested-face metrics, and its fallback width helper sums grapheme advances (`:486–495`), which does not measure joined Nastaliq words. Shape contiguous same-face runs, disable letter spacing for complex scripts, and test long descending Urdu words with diacritics at top/bottom positions. Do not switch fonts mid joining sequence. Use a pinned current upstream face rather than an arbitrary old copy. [Nastaliq releases](https://github.com/notofonts/nastaliq/releases).

Current worker geometry explicitly sets `words:null` whenever a fallback is used (`caption-ass.ts:408–415`). Adding Urdu glyphs therefore does not enable correctly placed per-word pills/emoji. Decide whether this effort implements shaped visual word boxes for fallback text, or specifies a shared typed degradation for unsupported motion. The spec presently promises the former without describing it.

For CJK, requested/display fonts can already contain Han glyphs; a language-aware font added only at the tail never wins. Define locale precedence for relevant script runs, with Japanese JP, Cantonese TC and a stated `zh` default, preserving deliberate custom-font behavior. “Traditional” is not represented by a separate source-language value here. Use the same precedence in browser and worker.

JP/TC will add megabytes of font assets. Existing SC/KR files are already about 7.9/4.4 MiB. These are static download/build assets, not necessarily JavaScript bundle bytes. `unicode-range` gates which **resource** downloads; it does not subset a large local file. Use static WOFF2 subsets if download size requires them, preserving shaping tables and metrics. `next/font/local` supports descriptor declarations and `preload:false`; retain that setting and restrict ranges so an English cue does not fetch every script face. Wait for font loading before trusting measured geometry. [Next font options](https://nextjs.org/docs/app/api-reference/components/font), [CSS font resource selection](https://www.w3.org/TR/css-fonts-4/#unicode-range-desc).

RTL is not “reverse the array” or “mirror every x.” Keep canonical chronological words. Derive base direction from strong bidi characters; isolate mixed Latin/numeric runs and position overlays from visual shaped order. `Encoding=-1` enables libass whole-line bidi/shaping, but is not evidence that `\kf` sweeps correctly right-to-left. Verify the pinned renderer; animated clipping is an upstream-described option if native karaoke fails. [libass extension](https://github.com/libass/libass/wiki/Libass%27-ASS-Extensions), [upstream RTL karaoke discussion](https://github.com/libass/libass/issues/406).

Define the coverage claim as Scribe-supported languages in their supported written forms, plus current supplied-caption behavior. Dhivehi/Thaana, Tamazight/Tifinagh and Cherokee are absent from the reviewed catalog, so adding them is scope expansion. Mongolian is listed, but vertical traditional Mongolian layout is a separate feature from ordinary Cyrillic Mongolian captions. State that limit. Fonts shared by browser/libass can deliver matching text/layout policy, not guaranteed identical raster pixels.

## 6. Standards and omitted operational work [P1/P2]

- **Body limits are a real blocker.** The blanket webhook middleware rejects above 1 MiB (`apps/api/src/app.ts:76`). Adding a larger limiter inside the route cannot override it. Bun's native cap is also **16 MiB**, derived from the editor limit (`http/limits.ts:42`), below the spec's 45 MB estimate. Add a dedicated bounded class and mutually exclusive route selection, update the native ceiling, and test real Bun ingress with Content-Length and chunked bodies. Keep all other route limits. Choose a tested maximum with memory headroom; extrapolating one English JSON size is not a maximum for character-token languages.
- Declare `POST /webhooks/elevenlabs` as `trust:"provider_signature"` in its owning domain admission, include it in inventory/runtime composition, and mount outside Clerk/workspace gating. API origin A owns it. Web must import only validators/API-client/UI, never provider/services/fontkit filesystem code.
- Preserve Processing Usage unchanged: source-duration settlement before STT; probe, provider retry, callback duplicate, regeneration and GET recovery do not debit again. Do not use provider last-word time as source duration. Add invariant coverage, not a second provider-credit ledger. ADR 0012 governs this.
- Define errors from nested ElevenLabs `detail` objects. Missing key/webhook configuration, authorization, exhausted paid quota, invalid media/language and malformed normalization need permanent dispositions; network/429/concurrency/5xx are bounded retryable cases. Only measured `404 detail.code=transcript_not_found` means pending until deadline. Other 404s and 401/403 must not masquerade as processing. Update `processing-retry-policy.ts`, safe error copy and tests; do not expose raw provider messages as user copy.
- Make normalizer identity explicit: `providerModel="scribe_v2"`, persisted job ID passed separately when GET JSON lacks it, seconds without millisecond conversion, finite times, stable speaker-ID mapping and nullable word confidence. Map arbitrary speaker strings to dense IDs; use one stable unknown bucket for partially missing IDs rather than collapsing known speakers. Scribe `logprob` is not an existing 0–1 confidence. Respect `allowEmpty`; do not manufacture words. [Transcript schema](https://elevenlabs.io/docs/api-reference/speech-to-text/get).
- Specify a conservative URL-size policy and signed-URL lifetime. Today's 591 MB success is evidence, not a guaranteed multi-GB limit. Async remote-fetch rejection happens after 202, so immediate-submit fallback alone cannot recover it. Retry with extracted current-source audio only for an identified fetch/size/media condition, once under a stated attempt policy. Stream files; never copy the existing whole-file Buffer pattern for large inputs.
- Replace provider stamps in `project.service.ts:137`, `ingest-job-lifecycle.ts:799/808`, and `workflow-run-lifecycle.ts:916`, not just the worker. Drain/reset pending AssemblyAI waits before enabling the new worker against shared dev data. Keep historical normalized transcripts; remove the old runtime completely. No provider selector, dual reads or compatibility adapter is justified.
- Regenerate `packages/api-client/src/openapi/public-v1.json`; verify REST and MCP schemas expose the same new language enum. Audit public docs, tool descriptions and UI model/accuracy labels for stale catalog claims. Update app-local env examples/checks and configure webhook ID/secret/retries on the deployed API before sending worker jobs. No root `.env`.
- Record ADR 0018 and index it; update ADR 0001 if provider-wait ownership gains the pre-submit transition. Preserve Worker Process Module rules. The 68-minute diarization result merged one voice: “two clean speakers” is not proof of faithful diarization. Test actual turn/layout behavior without adding out-of-scope threshold tuning.
