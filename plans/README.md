### Plan 020 postmortem (2026-07-07)

The Emotion-cache-registry step was abandoned. Its `bun install` (to add
`@emotion/cache`) re-resolved the **`"latest"`-pinned `@chakra-ui/react`**,
splitting it into two copies (`packages/ui`→3.36.0, `apps/web`→3.34.0). Two
Chakra instances = two React context objects, so `<ChakraProvider>` and `<Box>`
no longer shared context and **every route 500'd** with
`ContextError: … forgot to wrap component within <ChakraProvider />`. Fix:
pinned `@chakra-ui/react` to `3.34.0` and `@emotion/react` to `11.14.0` in both
`apps/web/package.json` and `packages/ui/package.json`, removed `@emotion/cache`
and the orphaned `emotion-cache-provider.tsx`, reinstalled → single Chakra copy,
`/`+`/pricing`+`/icon.svg` return 200, no ContextError. **Lesson: never ship
`"latest"` on a shared UI dep across workspace packages** — a stray reinstall
desyncs them. Kept from 020: OAuth start now redirects to
`/settings/social?error=<code>` instead of returning raw JSON, friendly
`social_oauth_*` messages, and the app favicon. NOT fixed (was out of 020's
scope): the `React.Children.only` console error and the Emotion streaming
hydration warning — both need the authenticated browser's full stack to locate.

## Findings considered and rejected (so they aren't re-audited)

Round 2 (2026-07-07):

- **Caption animation render parity ("not all 9 animations verified")** —
  REJECTED. The ASS export path handles the animation families explicitly
  (`render-clips.ts:488-531` maps word-by-word/karaoke/grow/bounce/
  seamless-bounce/soft-landing/blur-in/glitch/breathe) and ROADMAP documents
  preview==export as fixed June 2026 with a shared cue model.
- **Unmetered re-renders (`triggerClipRendering` has no quota gate)** —
  DEFERRED post-launch. Quota charges source minutes at generation by design;
  the intended secondary control is a 20/min request limit. Fresh verification
  found configured Redis limits currently fail open before connection, so do
  not rely on that control until reopened Plan 037 is complete. A render-minutes
  meter remains a future enhancement rather than this plan's scope.
- **Storage retention (Free 3-day / Creator 30-day auto-cleanup)** — DEFERRED
  post-launch. The pricing PAGE doesn't promise retention (only ROADMAP's
  recommended model does), and a destructive cleanup job written days before
  launch is worse risk than unbounded storage for the first cohort. Revisit
  with soft-delete + audit trail.
- **Presign fallback returns raw `errorMessage(error)`** — LOW/accepted. The
  handler already unwraps Quota/UploadTooLong into coded 402s; remaining
  fallback is generic and rare. Fold into a future route-wide error helper.
- **"Starter tier conflicts with ROADMAP"** — NOT a code bug. The 4-tier model
  in `packages/validators/src/pricing.ts` is the deliberate, Stripe-wired
  source of truth; the fix is doc sync (plan 018 step 5), not tier removal.
- **beforeunload can't guarantee the save completes** — partially by-design
  (no browser API guarantees it); the practical improvement (keepalive +
  pagehide flush) is plan 019 step 2.

- **"Secrets committed to git" / rotate-everything** — REJECTED. `.gitignore`
  covers `.env`, `.env.local`, `.env.*.local`; `git ls-files` shows only
  `.env.example` tracked; `git log` history has no `.env` files. Secrets live
  only in local dev files, as intended. (Subagents also leaked a real key value
  into their reports — do not propagate; still worth rotating that one key as
  hygiene since it appeared in tool output, but there is no VCS exposure.)
- **FFmpeg color/font filter injection** — REJECTED. Colors are zod-validated
  `^#[0-9A-Fa-f]{6}$` (`packages/validators/src/caption-preset.ts`) and font
  names are stripped to `[A-Za-z0-9 -]` (`render-clips.ts` `resolveFontName`).
- **Duplicate social-post publish race** — REJECTED. The conditional
  `updateMany({ where: { id, status: "scheduled" } })` is atomic at the row
  level; only one worker's update returns `count > 0`. No double-publish. (The
  real, minor residual — posts stuck in `publishing` after a worker crash with
  no reaper — is noted as a follow-up in plan 003.)
- **video-preview subscribe effect "missing cleanup"** — REJECTED. The effect
  returns `playbackClock.subscribe(...)`'s return value, which *is* the
  unsubscribe function used as the effect cleanup.
- **datetime-local timezone bug** — REJECTED. JS `new Date("YYYY-MM-DDTHH:mm")`
  parses a datetime-*without* offset as local time, so `.toISOString()` converts
  local→UTC correctly.
- **Multipart part-count validation** — RESOLVED by plan 034. Completion now
  validates the exact unique `1..UploadSession.partCount` ETag set on the
  server before the provider mutation; client checks remain defense in depth.
- **Stripe webhook replay alone** — `applyTier` is deterministic for one event,
  but the broader conclusion that Stripe is safe was rejected on re-verification.
  Stripe does not guarantee event order; stale updates/deletions can still
  overwrite newer entitlement truth. Plan 029 is a P1 release blocker.
