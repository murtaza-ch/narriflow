# Clip Composition Plan owns preview and render geometry policy

Narriflow resolves clip composition once through the browser-safe `@narriflow/composition-plan` deep module. Its single pure planning interface accepts a Clip Editor Document, stable source facts, bounded evidence and asset availability, startup capabilities, and one to four exact output targets. It returns an immutable, JSON-safe, versioned and size-bounded Clip Composition Plan containing edited-time scenes, ordered visual layers, source crops, output destinations, notices, evidence requests, and compact fingerprints. Center, Fit with background, Automatic Speaker Composition, explicit Split, Screen/PiP, B-roll, text, captions, logos, transitions, resolution treatment, and watermark treatment use this plan as their only video composition path.

Studio and FFmpeg are adapters. Studio translates the active planned scene and visual schedule into CSS while preserving the existing main media element and playback identity. The worker translates the same scene geometry and ordered schedule into FFmpeg filters and rejects unknown plan versions before starting a process. Inserted text Scenes carry target-specific planned lines, font size, line height, and maximum width; adapters render those values without fitting or wrapping text again. Neither adapter may select speakers, choose crops, resolve optional-asset fallback, apply manual speaker policy, independently decide target-specific eligibility, remap overlay timing, or reorder visual treatment. Manual speaker overrides, resolved logo settings, and output entitlement facts are planner inputs.

Scenes and visual schedules use final composition time, including inserted Scene Blocks. Each source scene also records the source range to read. The FFmpeg adapter trims that range, renders the scene's planned geometry, then concatenates it with inserted scenes. B-roll playback and motion stay on the final timeline; inserted blocks can interrupt its visible ranges without compressing its clock. Source crop tracks also use final composition time: inserting a Scene Block clips each source track to its visible fragment and shifts its keyframes by the inserted duration. Studio samples those tracks at its final playback time, and FFmpeg samples them relative to the compiled fragment start. Its playback clock holds an inserted scene independently of the paused source media; repeated source seek acknowledgements cannot skip that scene. Evidence smoothing and manual edit helpers do not choose render geometry.

Layout Evidence remains observations rather than composition truth. The injected worker `LayoutEvidence` owner binds Automatic, Screen, and Split evidence to original source identity and dimensions, the canonical Clip window, deleted ranges, and the current engine. It privately reuses durable success or matching typed failure, obtains one lazy complete-window segment, runs shared detectors, remaps observations to edited time, builds current envelopes, and publishes through the caller's revision and execution-owner fence. Background proxy analysis and Clip Render Attempt use this same interface. Detector coordinates are normalized, so proxy dimensions do not alter source geometry or zoom limits: Automatic permits at most 1.1 zoom regardless of source resolution. Automatic v3 binds shot subjects, no-face Fit intent, and bounded crop tracks; old derived evidence is reset and re-analyzed rather than read through a legacy parser. Background analysis obtains original dimensions through a bounded WorkerProcess probe using the Project's existing source key; it refuses partial proxy coverage.

The service-side `LayoutEvidenceLifecycle` owns preview publication and the Automatic analysis queue. Claims bind the editor revision, proxy identity and window, and a time-bounded token; expired or superseded tokens cannot publish. The service-owned claim runner renews those facts throughout analysis, combines shutdown and ownership signals for every media operation, and releases its current token immediately on shutdown. Ownership loss aborts work without becoming an analysis failure. Foreground render publication retains the Workflow Attempt fence. Missing or stale evidence produces one deduplicated planner request and a provisional Center plan in Studio. A Clip Render Attempt fulfills those requests and replans; failed or disabled evidence produces typed degraded composition. An unavailable persistence service leaves fresh frozen render evidence usable but logs the failed durable publication; lost execution ownership and cancellation propagate before publication. Matching durable failure remains failed without repeating expensive detection until its input binding changes. Unrelated document edits do not invalidate the evidence binding.

## Considered options

We rejected keeping parallel preview and FFmpeg geometry helpers because small rounding and fallback differences become user-visible export mismatches; putting FFmpeg strings in the planner because that would make a browser-safe policy module depend on one renderer; treating analysis output as a render plan because it cannot express target canvases, manual overrides, asset fallback, or adapter validation; and absorbing planning into Clip Render Attempt because execution ownership and composition policy are separate deep modules.

## Consequences

Plan version `2` is the only supported plan version; both adapters reject version `1` and any unknown version fail-closed. Plan inputs and diagnostics contain stable logical identities rather than signed URLs or storage access locations. Plans support at most four targets and 1 MiB of serialized policy output. Automatic evidence allows 128 scenes; explicit Split remains capped at 64. A measured 128-scene tracked plan with four targets is 639,263 bytes, so the previous 512 KiB plan budget could not support that boundary. Maximal 48-key tracks across all 128 scenes and four targets return the typed `plan_size_exceeded` error. The worker retains a separate default 512 KiB budget for each compiled FFmpeg command, including its filter expressions, and fails closed when exceeded. Inserted text must fit the centered 82% safe area at or above the target-scaled minimum size or planning returns the typed `text_scene_unfit` error. Fit resolves image availability before choosing image or selected-color fallback. Automatic Speaker Composition chooses full or no-split evidence per target and emits exact final-time scenes. Missing optional logo media omits only its planned layer and emits a scoped notice. The plan is the sole video composition path; analysis kill switches and optional-media failure degrade through typed plan notices instead of selecting another renderer.
