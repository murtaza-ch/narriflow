# Clip Render Attempts own render execution under Workflow Attempt fencing

A Clip Render Attempt is one execution of a `clip_rendering` Workflow Attempt, using the same immutable attempt ID and lease established by ADR 0001 rather than introducing child leases or retry counters. One deep module owns its fixed Render Work Set, Frozen Rendering State, asset resolution, command execution, bounded delivery, guarded variant persistence, aggregate settlement, notification enqueue, and cleanup behind a single `execute({ attempt, signal })` interface. Process, object-storage, media-analysis, temporary-workspace, clock, persistence, and diagnostic adapters remain deterministic internal seams so behavior tests drive the attempt interface instead of helper functions or command strings.

Each Clip Render Variant keeps durable Workflow Run lineage for work-set membership and an attempt-fenced claim for mutation. The work set is fixed when an attempt begins and never expands while executing; terminal settlement atomically admits an idempotent follow-up Workflow Run for later unassigned variants. Frozen Rendering State is attempt-local rather than a persisted full manifest, while export-bound variants continue to use their persisted clip revision, resolution, and watermark across attempts. Completion rejects stale attempts, every uploaded object key is attempt-unique, and `WorkflowAttemptLost` remains a control signal that aborts active work without recording a render failure or notification.

Variant failures are classified as retryable or permanent. Unrelated variants continue after a local failure, a shared encode failure affects every variant produced by that command, mixed surviving success and failure settles the Workflow Run as a Partial Workflow Outcome, and zero successful surviving variants fails or requeues the run according to the causal dispositions. Completed and permanently failed variants remain settled across retries; only interrupted or retryable variants return to pending. Workflow Event remains the transactional outbox: terminal outcome, notification intent, and follow-up admission are committed with fenced settlement before cleanup is considered complete.

## Considered options

We rejected an independent Render Attempt lease because it would create competing ownership truth; separate public plan, execute, and settle methods because callers and tests would have to reproduce sequencing; a persisted full render manifest because most inputs are already durable and expiring access locations must be refreshed; shared export object keys because stale attempts could overwrite or delete newer bytes; dynamic adoption of variants created mid-attempt because it makes settlement non-deterministic; fail-fast aggregate rendering because one bad variant should not discard independent outputs; and absorbing Clip Composition Plan policy because preview/render geometry parity is a separate architecture recommendation.

## Consequences

ADR 0001 remains the sole owner of Workflow Run claiming, heartbeats, retries, reaping, and attempt fencing, but its clip-rendering child-settlement interface must preserve per-variant failure disposition and Render Work Set lineage. The original migration rollout drained render workers before enabling attempts. Clip Render Attempt is now the only execution path. `WORKER_CLIP_RENDER_ATTEMPT_ENABLED` pauses or enables new claims without selecting another renderer; disabling it does not interrupt an active attempt. Drain workers before changing deployed render code. Render configuration is parsed once into an immutable validated value, operation deadlines and upload concurrency are bounded, structured diagnostics use stable phase and failure fields, and a project-scoped dry-run reconciliation command recovers attempt-unique orphaned objects.

## Implementation ownership

The injected attempt implementation lives in `clip-render-attempt.ts`; `clip-render-attempt-runtime.ts` supplies production adapters. The attempt still exposes only `execute()`. Scene visual assets and fonts are loaded through an injected persistence reader scoped to the frozen Workspace. The attempt validates their fingerprints, kinds, media and font facts before planning. Optional media retains the current typed degradation policy.

The FFmpeg adapter compiles a Clip Composition Plan and resolved input facts into one encoding command. Cut and audio filters, caption serialization, and video, B-roll and audiogram argument builders stay private to that adapter. Rendering has no legacy subtitle path: caption visibility and cues come from the plan. Attempt tests verify encoded media and fenced settlement through `execute()`; pure compiler tests exercise the adapter interface.
